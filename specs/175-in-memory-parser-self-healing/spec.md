## 1. Executive Summary & Problem Statement

Real-world PDF documents generated by legacy scanners, web scrapers, faulty email attachments, or incomplete downloads frequently violate ISO 32000 specifications. Common corruptions include:
1. Missing or truncated `%%EOF` markers.
2. Corrupted Cross-Reference Tables (`xref`) with broken byte offsets.
3. Prematurely terminated stream lengths (`/Length` mismatch).
4. Stray garbage bytes prefixed or suffixed around standard PDF delimiters.

Strict PDF parsers immediately fail on such files with fatal parse errors, halting automated batch pipelines and agent workflows.

**Spec 175** establishes an automatic, transparent **In-Memory Self-Healing Mechanism**:
When primary parser loading fails, PaperPilot automatically falls back to a non-destructive heuristic recovery pass in memory, reconstructing the xref table, repairing damaged object headers, synthesizing missing EOF markers, and resuming execution without writing temporary corrupted files to disk.

---

## 2. Technical Architecture & Self-Healing Pipeline

```
[ Input Document Bytes ]
           │
           ├──► 1. Attempt Primary Fast Load (LopdfDocument / standard xref)
           │      │
           │      ├──► Success ──► Proceed to Operation
           │      │
           │      └──► Error Encountered (Malformed xref, truncated EOF, stream fault)
           │
           └──► 2. Trigger In-Memory Self-Healing (`paperpilot-pdf::operations::repair`)
                  │
                  ├──► Pass A: Scan byte buffer for `%PDF-` header and trim leading garbage
                  ├──► Pass B: Scan backwards for valid object definitions and synthesize EOF
                  ├──► Pass C: Rebuild Cross-Reference Table from raw object offsets (`obj ... endobj`)
                  ├──► Pass D: Un-gzip and sanitize compressed streams where possible
                  │
                  └──► 3. Re-instantiate LopdfDocument from Healed Memory Buffer
                         │
                         ├──► Success: Log debug recovery notice & execute operation
                         └──► Permanent Failure: Return descriptive CorruptedDocumentError
```

## 3. Verification & Acceptance Criteria
1. Corrupted PDFs with missing `%%EOF` and broken `xref` tables load successfully during analytical operations (`pdf_info`, `pdf_search`, `pdf_extract_text`).
2. Self-healing operates 100% in memory with zero temporary files written to scratch or disk.
3. Automated unit tests pass: `cargo test -p paperpilot-pdf --test self_healing_test -j 4`.
