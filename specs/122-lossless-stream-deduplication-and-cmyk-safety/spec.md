# Spec 122: Lossless Object & Stream Deduplication (`pdf_dedup_streams`) & CMYK-Safe Recompression

## 1. Overview & Objective
PDF documents frequently contain duplicate binary assets:
- Repeated header/footer logos across 50–500 pages.
- Duplicate embedded font programs (TrueType/CFF subsets) generated by naive PDF print virtual drivers.
- Identical ICC color profiles attached to every image XObject.

Inspired by techniques proven in **Presse** (`SimonBure/presse`), this spec introduces:
1. **Lossless Object Stream Deduplication**: A fast hash-based pass that finds identical byte streams across the PDF DOM, merges them into a single canonical indirect object (`Object::Reference`), and updates all referencing dictionaries (Page `/Resources /XObject`, `/Font`, and `/ColorSpace`).
2. **CMYK-Safe Image Recompression**: Preserves `/DeviceCMYK` and CMYK ICC-profiled raster images without converting them to RGB JPEGs (which causes color-space distortion and prepress color shifts).
3. **Pure-Rust High-Throughput Stream Deflate**: Evaluates stream compression efficiency with optional `zlib-rs` compatibility for zero-C dependency SIMD acceleration.

---

## 2. Requirements & Deliverables

### Requirement 1: Lossless Stream Deduplication Pass
- In `paperpilot-pdf/src/operations/compress.rs` (or dedicated `dedup.rs`):
  - Iterate all stream objects in `lopdf::Document`.
  - Compute a 64-bit/128-bit hash (or SHA-256) of each uncompressed stream payload.
  - For stream collisions, verify byte-by-byte equality to guarantee 0% false positives.
  - When duplicate streams are detected:
    - Retain the first `ObjectId` as canonical.
    - Rewrite all occurrences of duplicate `ObjectId`s across all page dictionaries and resource dictionaries to point to the canonical `ObjectId`.
    - Prune orphaned duplicate objects via `lopdf_doc.inner.prune_objects()`.

### Requirement 2: CMYK Color Space Guard in `CompressOperation`
- In `paperpilot-pdf/src/operations/compress.rs`:
  - Inspect `/ColorSpace` in the stream dictionary before decoding.
  - If `/ColorSpace` is `/DeviceCMYK` or an `/ICCBased` CMYK profile:
    - Do NOT blindly convert to `DeviceRGB`.
    - Either perform CMYK-preserving JPEG compression (if 4-channel raw encoding is supported) or leave the original stream intact while applying Flate re-compression, avoiding visual artifacts and color distortion.

### Requirement 3: Automated Unit Testing
- Test in `paperpilot-pdf/src/operations/compress.rs`:
  - Synthesize a PDF with 5 identical 100x100 image streams referenced across 5 separate pages.
  - Assert that after compression/deduplication:
    - The output file size drops dramatically.
    - All 5 pages still render with valid image references.
    - The number of unique image stream objects in `doc.objects` is reduced from 5 to 1.
  - Synthesize a CMYK image stream and assert it is not corrupted or coerced into an invalid RGB format.

---

## 3. Success Criteria
- [ ] Duplicate byte-identical streams are collapsed to a single canonical object reference.
- [ ] No visual degradation or missing page assets.
- [ ] CMYK print/prepress PDFs retain original color space integrity.
- [ ] Zero-Mock tests pass via `cargo test -p paperpilot-pdf --lib operations::compress -j 2`.
