# Spec 100 — Penta-Scaffold UI Automation & Universal Audit/Report Visualizer

## 1. Overview & Problem Statement
`penta-scaffold` (Spec 094) successfully automates wiring for pure-Rust operations across:
- `paperpilot-pdf` (core runner & trait)
- `paperpilot-cli` (CLI command & handler)
- `paperpilot-mcp` (tool schema & runner)
- `paperpilot-gateway` (Axum REST route & handler)
- `paperpilot-wasm` (in-memory WASM method)
- `penta-interface-e2e` (E2E test suite & runner)

### The UI Gap:
However, for Desktop UI (`apps/desktop`):
1. `penta-scaffold` only inserts metadata into `toolList.ts`.
2. It **does NOT** wire `apps/desktop/src/lib/services/operationArgsBuilder.ts`. Any new tool generated by `penta-scaffold` falls back to the generic `default:` branch with hardcoded `.pdf` output extensions, even when the output format is `.json`, `.csv`, `.docx`, etc.
3. For tools returning structured audit reports (`outputFormat: '.JSON'`, e.g. `pdf_validate_signatures`, `document_pii_scan`, `pdf_validate_accessibility`), `OperationsPanel.svelte` lacks a generic, interactive result visualizer to display the findings (pass/fail badges, details, tree view) after execution.

---

## 2. Technical Requirements

### 2.1 Enhance `penta-scaffold` (`tools/penta-scaffold/src/generator.rs`)
1. **Auto-wire `operationArgsBuilder.ts`**:
   - In `tools/penta-scaffold/src/generator.rs`, implement `append_desktop_args_builder(&ScaffoldArgs, name_snake)`:
   - Read `apps/desktop/src/lib/services/operationArgsBuilder.ts`.
   - In `buildOperationArgs(toolId, context)`, if `case '{name_snake}':` is not present, insert:
     ```typescript
             case '{name_snake}':
                 args = {
                     input: docPath,
                     output: customOutputPath || getOutputPath(`${docName.replace(/\.[^.]+$/i, '')}_output.{output_format_lc}`)
                 };
                 break;
     ```
   - Automatically respects `args.output_format.to_lowercase()`.
2. **Auto-wire `operationArgsBuilder.test.ts`**:
   - Append a test case ensuring `buildOperationArgs('{name_snake}', mockContext)` returns valid `input` and `output` paths.

### 2.2 Universal JSON Audit & Report Visualizer in `OperationsPanel.svelte`
1. For any tool whose `activeTool.outputFormat === '.JSON'` or is tagged as an audit/security scanner:
   - When the operation completes successfully, read the output file or parse returned JSON.
   - Display a clean **`<AuditReportViewer />`** card inside the OperationsPanel execution result drawer.
   - Format:
     - 🛡️ Summary Pill: Status (`Passed` / `Issues Detected`), total findings count, execution duration.
     - 📋 Formatted Tree / Key-Value table for properties (e.g. `signatures`, `pii_matches`, `violations`).
     - 📋 Copy JSON / Open File button.

### 2.3 Retrofit Recently Completed Tools
Ensure `operationArgsBuilder.ts` and `OperationsPanel.svelte` fully support:
- `pdf_validate_signatures`
- `document_pii_scan`
- `pdf_extract_tables`

---

## 3. Verification & Acceptance Criteria
1. `cargo run -j 2 -p penta-scaffold -- --dry-run ...` demonstrates proper injection into `operationArgsBuilder.ts`.
2. `pnpm --dir apps/desktop test` passes all Vitest unit tests (including `operationArgsBuilder.test.ts`).
3. Running `pdf_validate_signatures` or `document_pii_scan` in Desktop UI displays the structured findings cleanly in the UI.
