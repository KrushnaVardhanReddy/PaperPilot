## 2. Requirements for `scripts/test_tri_interface_e2e.py`

1. **Add Metadata to Every Tool Definition**:
   In `tools_definitions`, enrich each tool entry with:
   - `tool_id`: The canonical tool name (e.g. `pdf_merge`).
   - `use_case`: A concise 1-sentence description explaining the input document(s) and the operation being performed.
   - `expected_desc`: Human-readable expectation (e.g. `"Valid 2-page PDF (%PDF-)"`, `"JSON with 3 form fields"`, `"Rendered PNG image (> 5 KB)"`, `"Extracted text containing 'Chapter 1'"`).
   - `expected_type`: Output classification: `"pdf"`, `"json"`, `"text"`, `"image"`, `"dir"`, etc.
   - `expected_pages`: (optional integer) Exact expected page count if output is a PDF.
   - `wasm_supported`: Boolean flag or snippet if operation is available in WASM / Edge.

2. **Implement Artifact Deep Validation**:
   When recording the execution result, inspect the generated output file or stdout:
   - For PDFs:
     - Check file exists and size > 0.
     - Check file starts with `%PDF-`.
     - Count pages by inspecting `/Type /Page` dictionary objects or standard regex (`len(re.findall(rb'/Type\s*/Page\b', content))`).
     - Record actual summary: `f"Valid PDF, {pages} pages, {size:,} bytes"`.
   - For text / CSV / JSON outputs:
     - Check file exists and size > 0.
     - Record actual summary: `f"Valid {ext.upper()} file, {size:,} bytes"`.
   - For query / stdout operations without file output (e.g. `hash`, `search`, `classify`):
     - Parse JSON output.
     - Record actual summary: `f"Success: {parsed_summary}"`.

3. **Report Generation**:
   Update report template generation logic in `test_tri_interface_e2e.py` to render the clean Markdown comparison table illustrated above with `Tool` as the first column.
   Write to both `reports/TRI_INTERFACE_E2E_100_VERIFIED.md` and `reports/TRI_INTERFACE_E2E_AND_DOCS.md`.
