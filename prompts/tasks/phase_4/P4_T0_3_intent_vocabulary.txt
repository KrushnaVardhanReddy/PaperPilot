Hey Jules! We are starting on Phase 4 (the AI Layer) specifically targeting the Free Tier Offline NLP engine (`paperpilot-nlp`). 

Before we build the classification engine (Layer 1 Keyword/Regex and Layer 2 ONNX), we need to clearly define the canonical "Intent Vocabulary" mapping.

---

## Context

Our core `paperpilot-pdf` crate supports ~34 operations. Users will type natural language commands like:
- "combine these files" -> `Intent::Merge`
- "pull out the pictures" -> `Intent::ExtractImages`
- "lock it with a password" -> `Intent::Encrypt`

We need a central, canonical Rust `enum Intent` representing every supported operation, along with metadata (canonical name, English aliases/synonyms) that our rule-based keyword matcher will use later to classify user inputs.

---

### 2. Define the Metadata Structure

Define a struct to hold the definition for an intent:
```rust
pub struct IntentDefinition {
    pub intent: Intent,
    pub canonical_name: &'static str,
    pub description: &'static str,
    pub aliases: &'static [&'static str],
}
```

### 3. Implement a Global Registry

Implement a static registry or a function that returns the full list of `IntentDefinition`s. 

```rust
impl Intent {
    /// Returns the definition, including synonyms/aliases for the intent
    pub fn definition(&self) -> IntentDefinition { ... }

    /// Returns all registered intents
    pub fn all() -> Vec<Intent> { ... }
}
```

For the `aliases`, think deeply about how a non-technical user might describe the operation. 
Examples:
- `Intent::Merge`: "merge", "combine", "join", "append", "concat", "put together"
- `Intent::ExtractImages`: "extract images", "rip pictures", "get photos", "pull out graphics"
- `Intent::Rotate`: "rotate", "turn", "spin", "flip"
- `Intent::Compress`: "compress", "shrink", "reduce size", "make smaller", "optimize"

Provide at least 3-5 high-quality aliases for every single intent.

### 4. Export from `paperpilot-nlp`

In `paperpilot-nlp/src/lib.rs`, add:

