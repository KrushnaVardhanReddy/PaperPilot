Hey Jules! We have a working `OfflineNlpResolver` (which turns text into an `OperationPlan`) and our MCP server which executes operations. Now we need the ultimate integration test for the AI stack: parsing a real natural language query and dispatching it successfully as an MCP tool call to modify a real file.

## What to Build

Create an E2E test file at `paperpilot-nlp/tests/nlp_e2e_dispatch_test.rs`.

### 1. Test Setup
- In your test, spin up an instance of the `OfflineNlpResolver`.
- Programmatically create a real dummy PDF file (e.g. `tests/fixtures/e2e_test.pdf`) with 1 page using `lopdf` or just a hardcoded dummy PDF byte array so we have something real to operate on.

### 2. The Full Flow Test
Write a test `#[test] fn test_full_nlp_to_mcp_dispatch()` that does exactly this:
1. **Input:** Define a natural language string: `"Please rotate e2e_test.pdf by 90 degrees"`
2. **Resolve:** Pass it through `OfflineNlpResolver::resolve()` to get an `OperationPlan` (Intent: Rotate, Args: e2e_test.pdf, 90).
3. **Dispatch:** Map the `OperationPlan` to the equivalent MCP tool payload (`pdf_rotate`).
4. **Execute:** Call the actual underlying PDF operation function (or the MCP handler directly) using those arguments.
5. **Verify:** Check that the output PDF (`e2e_test_rotated.pdf`) actually exists on disk.

### 3. Cleanup
Ensure the test cleans up the generated PDF files after it finishes.

## Rules & Constraints
- Do NOT use mocks. This must be a real end-to-end test hitting the filesystem.
- Make sure `cargo test -p paperpilot-nlp` passes.
- Make sure `cargo clippy --workspace` has 0 warnings.
- Commit the changes and exit.
