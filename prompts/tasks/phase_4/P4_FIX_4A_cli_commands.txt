## Required Fixes (Verified via `paperpilot --help`)

### 1. `annotate.rs` — Support both file path and inline JSON string for `--data`
**File:** `paperpilot-cli/src/commands/annotate.rs`
**Issue:** `handle_annotate` currently calls `fs::read_to_string(data)` assuming `--data` is always an existing file path. When a user or test passes inline JSON (`--data '[{"type":"note",...}]'`), it fails with `I/O error: No such file or directory`.
**Fix:**
- Check if `data` is an existing file path:
  - If yes, read string from file with `fs::read_to_string(data)`.
  - If no (or if the path string starts with `[` or `{`), treat `data.to_string_lossy()` directly as the JSON string!
- Parse the resulting string into `Vec<AnnotationParams>`.

### 2. `group_a.rs` — Ensure output directory exists in `burst`
**File:** `paperpilot-cli/src/commands/group_a.rs`
**Issue:** `handle_burst` passes `output` to `BurstOperation`. If the output directory does not exist, writing `page_1.pdf` inside it fails with `I/O error: No such file or directory`.
**Fix:**
- In `handle_burst`, call `std::fs::create_dir_all(output)?;` before executing `op.execute(&mut doc)`.

### 3. `cli.rs` — Add intuitive subcommand aliases
**File:** `paperpilot-cli/src/cli.rs`
**Issue:** Subcommand naming discrepancies:
- `signature`: Add `#[command(alias = "sign")]` so both `paperpilot signature` and `paperpilot sign` work.
- Add aliases for common conversion subcommands or aliases matching user expectations:
  - `#[command(alias = "to-pdf-a")]` on `PdfA`
  - Under `Commands`, add convenience conversion subcommands if appropriate or alias them.
