## CONTEXT & OBJECTIVE

Currently, when a user runs a PDF operation (e.g. Merge, Compress, Encrypt), the output file is written
to a path automatically constructed from the source file's directory with a generated filename
(e.g. `Krushna_Passport_merged.pdf` in the same folder as the input).

This is invisible and confusing:
- The user doesn't know where the file was saved.
- The user cannot choose the filename.
- For **Merge** and **Split**, the output destination is especially critical since the result is a new document.

### Goals

1. **For Merge & Split** — show a native **"Save As" dialog** before running the operation, letting the user pick both
   the output filename and directory. Use Tauri's `save()` from `@tauri-apps/plugin-dialog`.

2. **For all other single-file operations** — show an **editable output path field** in the tool inspector
   (pre-filled with the auto-suggested path based on source file), so the user can accept or change it
   before hitting "Run".

3. The success toast must always show the **full absolute path** of the saved file.

## STEP 1: Add Save-As for Merge & Split in `OperationsPanel.svelte`

File: `apps/desktop/src/lib/components/layout/OperationsPanel.svelte`

### 1A — Import Tauri save dialog (lazy import, already available as a plugin dependency)

In `handleRunOperation`, for the `merge` and `split` cases, **before invoking the MCP tool**, call:

```typescript
const { save } = await import('@tauri-apps/plugin-dialog');
```

### 1B — Merge case: show Save-As dialog

Replace the current merge args block:
```typescript
case 'merge': {
  const suggested = `${docName.replace(/\.pdf$/i, '')}_merged.pdf`;
  const outputPath = await save({
    title: 'Save Merged PDF As...',
    defaultPath: suggested,
    filters: [{ name: 'PDF Document', extensions: ['pdf'] }]
  });
  if (!outputPath) return; // user cancelled
  args = {
    inputs: appState.documents.map((d, i) => appState.documentPaths[i] || d.name),
    output: outputPath
  };
  break;
}
```

### 1C — Split case: show folder picker

Replace the current split args block:
```typescript
case 'split': {
  // Note: Tauri plugin-dialog does not have a native folder-only picker in all versions.
  // Use save() with a sentinel filename to let the user pick the destination folder+prefix.
  const suggested = `${docName.replace(/\.pdf$/i, '')}_split`;
  const outputPath = await save({
    title: 'Save Split PDFs to Folder (choose base filename)...',
    defaultPath: suggested,
    filters: [{ name: 'PDF Document', extensions: ['pdf'] }]
  });
  if (!outputPath) return; // user cancelled
  // Strip extension if user typed one; the split operation appends _pageN.pdf automatically.
  const outputDir = outputPath.replace(/\.pdf$/i, '');
  args = {
    input: docPath,
    output_dir: outputDir
  };
  break;
}
```

## STEP 2: Add editable output path for all other tools

### 2A — Add reactive state for the output path field

In the `<script>` section of `OperationsPanel.svelte`, add:

```typescript
let customOutputPath = $state('');

// Auto-fill the output path whenever the active tool or selected document changes
$effect(() => {
  if (!activeTool || appState.documents.length === 0) {
    customOutputPath = '';
    return;
  }
  const docIndex = appState.selectedDocumentIndex ?? 0;
  const docName = appState.documents[docIndex]?.name || '';
  const docPath = appState.documentPaths[docIndex] || docName;
  const docDir = docPath.includes('/') ? docPath.substring(0, docPath.lastIndexOf('/')) : '';
  const getOutputPath = (filename: string) => docDir ? `${docDir}/${filename}` : filename;
  const base = docName.replace(/\.pdf$/i, '');

  switch (activeTool.id) {
    case 'merge':
    case 'split':
      customOutputPath = ''; // handled by native dialog
      break;
    case 'compress':   customOutputPath = getOutputPath(`${base}_compressed.pdf`);  break;
    case 'rotate':     customOutputPath = getOutputPath(`${base}_rotated.pdf`);     break;
    case 'watermark':  customOutputPath = getOutputPath(`${base}_watermarked.pdf`); break;
    case 'encrypt':    customOutputPath = getOutputPath(`${base}_encrypted.pdf`);   break;
    case 'decrypt':    customOutputPath = getOutputPath(`${base}_decrypted.pdf`);   break;
    case 'metadata':   customOutputPath = getOutputPath(`${base}_metadata.pdf`);    break;
    case 'extract_pages': customOutputPath = getOutputPath(`${base}_extracted.pdf`); break;
    case 'extract_text':
    case 'ocr':        customOutputPath = getOutputPath(`${base}_text.txt`);        break;
    default:           customOutputPath = getOutputPath(`${base}_output.pdf`);      break;
  }
});
```

### 2B — Use `customOutputPath` in the args switch

For all non-merge, non-split cases, replace `output: getOutputPath(...)` with `output: customOutputPath`.

Example for compress:
```typescript
case 'compress':
  args = {
    input: docPath,
    output: customOutputPath
  };
  break;
```
Apply the same pattern to all remaining cases: `rotate`, `watermark`, `encrypt`, `decrypt`, `metadata`, `extract_pages`, `extract_text`/`ocr`, and `default`.

### 2C — Render the editable output path field in the inspector

In the inspector template, just before the **Run** button (look for `id="btn-run-operation"` or similar),
add an output path row **only for tools that are NOT merge or split**:

```svelte
{#if activeTool && activeTool.id !== 'merge' && activeTool.id !== 'split'}
  <div class="operation-config" id="output-path-config">
    <label for="output-path-input" class="section-desc">Output file:</label>
    <div class="output-path-row">
      <input
        id="output-path-input"
        type="text"
        class="form-input output-path-input"
        bind:value={customOutputPath}
        placeholder="Output file path..."
        title="Edit the output file path"
      />
    </div>
  </div>
{/if}
```

if (resObj && resObj.success) {

    : (resObj.message || `${activeTool.title} completed successfully`);

}
