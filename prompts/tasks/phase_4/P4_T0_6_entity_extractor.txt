Hey Jules! We have a working Intent classifier in `paperpilot-nlp` (via the Aho-Corasick rule engine in `layer1.rs`). Now we need to extract the *arguments* for those intents from the natural language string.

## Context
When a user says "merge a.pdf and /docs/b.pdf and save to output.pdf", our `RuleEngine` identifies `Intent::Merge`. But we still need to pull out the file paths to actually build the `OperationPlan`.

This is where the Entity Extractor comes in. It uses simple regex heuristics to pull out common PDF arguments: file paths, page ranges, passwords, and rotation angles.

## What to Build

### 1. Dependencies
Add `regex` and `lazy_static` to `paperpilot-nlp/Cargo.toml`.

### 2. ExtractedEntities Struct
Create a new file `paperpilot-nlp/src/entities.rs` and expose it in `lib.rs`.

Define a struct to hold extracted data:
```rust
#[derive(Debug, Default, PartialEq)]
pub struct ExtractedEntities {
    pub files: Vec<String>,
    pub page_ranges: Vec<String>,
    pub passwords: Vec<String>,
    pub angles: Vec<i32>,
}
```

### 3. Regex Patterns
Define compiled Regex patterns using `lazy_static!` for efficiency.
- **Files**: Match typical file paths or strings ending in `.pdf` (e.g., `foo.pdf`, `/var/tmp/bar.pdf`, `"my document.pdf"`).
- **Page Ranges**: Match strings like `1-5`, `page 3`, `pages 2,4,6`.
- **Angles**: Match numbers commonly associated with rotation: `90`, `180`, `270`, `-90` (bonus points if it checks for the word "degrees" or "rotate" nearby, but simple regex catching 90/180/270 is fine for now).
- **Passwords**: Extract strings appearing after "password is" or "pw ".

### 4. Extraction Logic
Implement an extraction function:
```rust

    // ... apply regex patterns and populate the struct
}
```

### 5. Tests
Write unit tests in `entities.rs`.
- Test extracting multiple files: `"merge a.pdf and b.pdf"`
- Test extracting a page range: `"extract pages 1-5 from doc.pdf"`
- Test extracting an angle: `"rotate 90 degrees"`
