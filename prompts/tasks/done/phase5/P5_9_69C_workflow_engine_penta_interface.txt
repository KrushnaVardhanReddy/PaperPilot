## 1. Core Workflow Schema & Presets (`paperpilot-core/src/workflow.rs`)
Define serializable structs matching the `SavedPipeline` schema from Spec 081 & `apps/desktop/src/lib/state/pipeline.svelte.ts`:

```rust
use serde::{Deserialize, Serialize};
use std::collections::HashMap;

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct WorkflowStep {
    pub id: String,
    #[serde(rename = "operationId", alias = "operation_id")]
    pub operation_id: String,
    #[serde(default)]
    pub label: Option<String>,
    #[serde(default)]
    pub icon: Option<String>,
    #[serde(default)]
    pub params: HashMap<String, serde_json::Value>,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct SavedWorkflow {
    pub id: String,
    pub name: String,
    #[serde(default)]
    pub description: Option<String>,
    pub steps: Vec<WorkflowStep>,
    #[serde(rename = "updatedAt", alias = "updated_at")]
    pub updated_at: String,
    #[serde(default, rename = "isPreset", alias = "is_preset")]
    pub is_preset: bool,
    #[serde(default, rename = "teamId", alias = "team_id")]
    pub team_id: Option<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WorkflowExecutionReport {
    pub workflow_id: String,
    pub workflow_name: String,
    pub steps_total: usize,
    pub steps_completed: usize,
    pub output_bytes_len: usize,
    pub duration_ms: u64,
}
```

Implement standard presets helper functions:
- `get_default_presets() -> Vec<SavedWorkflow>`
- `get_preset_by_id(id: &str) -> Option<SavedWorkflow>`:
  - `legal-discovery` / `preset-legal-discovery`: `pdf_bates` -> `pdf_watermark` -> `pdf_linearize`
  - `clean-scan` / `preset-clean-scan`: `pdf_remove_blank` (or `pdf_rotate`) -> `pdf_page_numbers` -> `pdf_compress`
  - `redact-protect` / `preset-redact-protect`: `pdf_redact` -> `pdf_flatten` -> `pdf_encrypt`

Export `workflow` module in `paperpilot-core/src/lib.rs`.

## 2. In-Memory Sequential Workflow Pipeline (`paperpilot-pdf/src/operations/workflow.rs`)

pub fn run_workflow(
    input_bytes: &[u8],
    workflow: &SavedWorkflow,

- Each step takes the output buffer of the previous step as its input buffer.
- Map `step.operation_id` to existing `paperpilot_pdf::operations::*` implementations (e.g. `bates`, `watermark`, `linearize`, `compress`, `encrypt`, `flatten`, `page_numbers`, `rotate`, etc.).

- Return the final resulting PDF byte buffer along with execution summary metadata (`WorkflowExecutionReport`).

## 4. Agent MCP Server Tools (`paperpilot-mcp/src/server.rs`)
Provide 2 dedicated tools for AI agents:

1. **`list_workflows` / `list_workflow_presets`**:
   - Description: "List all available built-in multi-step document workflow presets (e.g. legal-discovery, clean-scan, redact-protect) with their constituent steps and parameters."
   - Parameters: `{}` (empty schema).
   - Returns: JSON list of available presets and descriptions.

2. **`document_workflow`**:
   - Description: "Execute a declarative multi-step PDF pipeline workflow (preset or custom JSON recipe). Allows AI agents to run compound operations such as Bates stamping, watermarking, flattening, pagination, compression, and encryption against an input PDF in a single tool call."
   - Parameters:
     - `input`: Path to input PDF file (required)
     - `output`: Path to output PDF file (required)
     - `preset`: Optional string preset name (`legal-discovery`, `clean-scan`, `redact-protect`)
     - `recipe`: Optional JSON string or object matching `SavedWorkflow`
   - Returns: Summary confirmation with steps completed and output file size.

## 5. REST Gateway Endpoints (`paperpilot-gateway`)
In `paperpilot-gateway/src/handlers.rs` & `paperpilot-gateway/src/server.rs`:
- **`GET /api/v1/workflow/presets`**:
  - Returns `200 OK` with JSON array of default presets and their step configurations.
- **`POST /api/v1/workflow/validate`**:
  - Validates a recipe JSON payload or preset name without executing; returns `{ valid: true, steps_count: N }` or `{ valid: false, error: "..." }`.
- **`POST /api/v1/workflow/run`**:
  - Multipart upload containing `file` (PDF bytes) and either `preset` field or `recipe` field (JSON).
  - Returns processed PDF binary stream (`application/pdf`) with custom response headers (`X-Workflow-Steps-Executed`, `X-Workflow-Duration-Ms`).
- **`POST /api/v1/workflow/run-json`**:
  - Accepts JSON payload:
    ```json
    {
      "input": "path/to/input.pdf",
      "output": "path/to/output.pdf",
      "preset": "legal-discovery",
      "recipe": null
    }
    ```
  - Returns JSON `{ "status": "success", "steps_executed": N, "duration_ms": M, "output": "..." }`.
