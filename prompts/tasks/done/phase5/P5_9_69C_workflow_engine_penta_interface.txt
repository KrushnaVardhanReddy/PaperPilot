## Objective
Implement declarative multi-step workflow execution natively in Rust using the **"Single Core Engine + 5 Thin Wrappers"** architecture.
A single pure in-memory execution function (`run_workflow_bytes`) processes the pipeline from byte buffer to byte buffer, and each of the 5 interfaces (CLI, MCP, REST Gateway, WASM Engine, Edge Worker) serves strictly as a thin 5-line adapter calling that single function.

3. **Execute / Start Workflow with Input**: Pass input document bytes or file paths, run the entire multi-step pipeline sequentially in memory, and produce the final artifact without disk roundtrips.

        steps_total: workflow.steps.len(),
        steps_completed: completed,
        output_bytes_len: current_bytes.len(),
        duration_ms: start.elapsed().as_millis() as u64,

## 3. THE 5 THIN INTERFACE WRAPPERS

Each of the following 5 interfaces MUST ONLY be a thin adapter calling `run_workflow_bytes`:

### Wrapper 1: Native CLI (`paperpilot-cli/src/commands/workflow.rs`)
- Read file from disk: `let bytes = std::fs::read(&input)?;`
- Resolve workflow: `let wf = load_preset_or_file(preset, recipe)?;`
- Call core runner: `let (out_bytes, report) = run_workflow_bytes(&bytes, &wf)?;`
- Write file to disk: `std::fs::write(&output, out_bytes)?;`
- Subcommands supported in `paperpilot-cli/src/cli.rs`:
  - `paperpilot workflow list` (prints table of `get_default_presets()`)
  - `paperpilot workflow inspect --preset <id>` (prints step sequence and params)
  - `paperpilot workflow run --input in.pdf --output out.pdf [--preset <id> | --recipe <path>]`

### Wrapper 2: Agent MCP Server (`paperpilot-mcp/src/server.rs`)
Provide 2 dedicated tools:
1. `list_workflows`: Returns JSON from `paperpilot_core::workflow::get_default_presets()`.
2. `document_workflow`:
   - Arguments: `input` (path), `output` (path), `preset` (optional), `recipe` (optional).
   - Reads input path -> calls `run_workflow_bytes` -> writes output path.
   - Returns confirmation JSON containing `WorkflowExecutionReport`.

### Wrapper 3: REST Gateway (`paperpilot-gateway/src/handlers.rs` & `server.rs`)
- `GET /api/v1/workflow/presets`: Returns JSON array of presets.
- `POST /api/v1/workflow/validate`: Validates recipe JSON without executing.
- `POST /api/v1/workflow/run`:
  - Multipart upload receives `file` bytes and `preset` or `recipe`.
  - Calls `run_workflow_bytes(&file_bytes, &wf)`.
  - Returns raw PDF binary (`application/pdf`) with `X-Workflow-Steps-Executed` and `X-Workflow-Duration-Ms` headers.
- `POST /api/v1/workflow/run-json`:
  - Accepts JSON `{ "input": "...", "output": "...", "preset": "..." }`, reads input, calls `run_workflow_bytes`, writes output, returns JSON summary.

### Wrapper 4: Browser WASM Engine (`paperpilot-wasm/src/operations.rs` & `lib.rs`)
- Expose `workflow_presets() -> String`: Returns JSON list of presets.
- Expose `workflow(input_bytes: &[u8], recipe_json: &str) -> Result<Vec<u8>, anyhow::Error>`:
  - Parses recipe or resolves preset by ID.
  - Calls `run_workflow_bytes(input_bytes, &wf)`.
  - Returns `Vec<u8>` directly to JavaScript as `Uint8Array`.

### Wrapper 5: Cloudflare Edge Worker (`apps/edge/src/index.ts`)
- `GET /api/v1/workflow/presets`: Returns presets list.
- `POST /api/v1/workflow`:
  - Receives request body buffer.
  - Calls `WasmPdfEngine.workflow(bytes, recipeOrPreset)`.
  - Returns `new Response(outputBytes, { headers: { "Content-Type": "application/pdf" } })`.
