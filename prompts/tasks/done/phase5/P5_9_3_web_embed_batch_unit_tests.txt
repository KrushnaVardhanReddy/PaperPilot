## 1. Test Requirements

### A. Embed Widget Unit Tests (`apps/embed/tests/widget_batch_and_config.spec.ts`)
Create Playwright tests verifying the embedded widget behavior:
1. **Interactive Config Panel Activation**:
   - Clicking `Extract Pages` opens `.pp-config-panel` with `#page-input`.
   - Clicking `Rotate Pages` opens rotation angle dropdown and page targets.
   - Clicking `Watermark` opens watermark text stamp input.
   - Clicking `Merge PDFs` shows the contextual merge info note.
2. **Page Range Parsing & Inputs**:
   - Verify typing custom values into `#page-input` (e.g. `1`, `2-3`, `1, 3`) binds properly to the state.
3. **Batch Processing (Multiple Files Uploaded)**:
   - When 2 PDFs are dropped and a non-merge tool (`extract`, `rotate`, `watermark`, or `compress`) is executed:
     - Verify it generates **2 separate download cards** in `.pp-download-container`.
     - Verify each download card contains the corresponding output filename.
4. **Merge Single Output Verification**:
   - When 2 PDFs are dropped and `Merge PDFs` is executed:
     - Verify it produces **1** aggregated download card (`merged_document.pdf`).

### B. Web WASM Operations Batch Processing Tests (`apps/web/tests/operations_batch_processing.spec.ts`)
Create Playwright tests for `apps/web` (`OperationsView.svelte`):
1. **Multi-File Queueing in Per-Document Tools**:
   - For `Split`, `Rotate`, `Compress`, `Extract`, and `Delete`:
     - Test dropping 2 PDF files into the tool pane.
     - Verify both files are displayed in `.file-list`.
     - Verify individual remove (`✕`) button removes the specific file from the queue.
2. **Dynamic Action Button Labels**:
   - Verify the action button reactively updates its label to reflect the count (e.g. `Extract Pages & Download (2 files)` or `Compress & Download (2 files)`).
3. **Batch Execution & Staggered Download Triggering**:
   - Mock/trigger the action and verify `wasmPdfClient` methods are invoked for every file in the batch queue.
