## 1. Requirements & Features

### A. CLI Interface (`tools/jules-submit`)
Implement using `clap` (derive):
- `--list`: List all pending task prompts under `prompts/tasks/` (recursively, excluding `done/`).
- `--file <path>`: Submit a specific prompt file.
- `--task <id>`: Fuzzy-find by task ID (e.g. `P1-T1` or `P5_7_1`).
- `--phase <num>`: Batch-submit all pending prompts in `prompts/tasks/phase{N}/`.
- `--branch <name>`: Target Git starting branch (default: `main`).
- `--dry-run`: Format payload and display target without making network call.

### B. Environment & API Key Handling
- Automatically check `JULES_API_KEY` from process environment.
- If not set, parse `.env.local` or `.env` in repository root.
- Never log or print the API key to console.

### C. Submission & Safety Rule Injection
- Target URL: `https://jules.googleapis.com/v1alpha/sessions`
- Prepend the mandatory `SAFETY_RULES` block to prompt text.
- Header: `x-goog-api-key: <KEY>`, `Content-Type: application/json`.
- Payload structure:
  ```json
  {
    "prompt": "<SAFETY_RULES + PROMPT_CONTENT>",
    "sourceContext": {
      "source": "sources/github/KrushnaVardhanReddy/PaperPilot",
      "githubRepoContext": { "startingBranch": "<BRANCH>" }
    }
  }
  ```
- Parse returned JSON session ID from `name` field (e.g. `sessions/<ID>`).
- Print the live dashboard link: `https://jules.google.com/session/<ID>`.

### D. Atomic Archiving
- Upon successful session creation, move prompt file to `prompts/tasks/done/<relative_path>`, preserving folder hierarchy.
