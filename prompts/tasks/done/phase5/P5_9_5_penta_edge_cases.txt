## 44-Tool Edge Case & Parameter Matrix

### 1. Page Operations (9 Tools)
1. `pdf_merge`:
   - Empty input array (`[]`) -> Assert clean exit code 1 or 400 error (cannot merge 0 files).
   - Single input file (`merge_a.pdf`) -> Valid 1-page output.
   - Duplicate inputs (`merge_a.pdf`, `merge_a.pdf`) -> Valid 2-page merged output.
2. `pdf_split`:
   - Out-of-bounds page range (`--pages 99-100` on 5-page PDF) -> Structured error code.
   - Discontinuous page intervals (`--pages 1,3,5`).
   - Boundary split on 1-page document (`--pages 1`).
3. `pdf_extract_pages`:
   - Reverse page order (`--pages 5,4,3,2,1`).
   - Discontinuous intervals (`--pages 1,3,5`).
   - Out-of-bounds page index (`--pages 99`).
4. `pdf_delete_pages`:
   - Deleting page 1 only.
   - Attempting to delete ALL pages (`--pages 1-5` on 5-page PDF) -> Assert error (cannot create 0-page document).
5. `pdf_reorder_pages`:
   - Full reverse order (`--order 5,4,3,2,1`).
   - Identity permutation (`--order 1,2,3,4,5`).
6. `pdf_rotate`:
   - Negative degree rotation (`--degrees -90` -> 270° normalized).
   - Full 360° and 720° rotation (invariant geometry).
   - Rotating single target page in multi-page document (`--pages 2 --degrees 90`).
7. `pdf_crop`:
   - Full-bleed media box crop (`--rect 0,0,612,792`).
   - Microscopic crop rectangle (`--rect 50,50,5,5`).
   - Target page specific crop (`--pages 1 --rect 10,10,100,100`).
8. `pdf_burst`:
   - Burst on 1-page document (produces exactly 1 file).
   - Burst on 10-page document (produces exactly 10 discrete files).
9. `pdf_remove_blank`:
   - Document with zero blank pages (preserves all pages).
   - Document containing blank pages interspersed.

### 2. Security, Stamping & Forms (14 Tools)
10. `pdf_encrypt`:

    - Distinct user vs owner passwords (`--user-password user123 --owner-password admin123`).
11. `pdf_decrypt`:
    - Wrong password on encrypted document (`wrongpassword`) -> Assert graceful authentication failure.
    - Decrypting already-unencrypted document -> Clean error or passthrough without panic.
12. `pdf_redact`:
    - Full-page redaction (`--rect 0,0,612,792`).
    - Tiny coordinate redaction (`--rect 10,10,5,5`).
13. `pdf_sign`:

14. `pdf_hash`:

15. `pdf_watermark`:

    - Extreme opacity and rotation angles.
16. `pdf_header_footer`:

17. `pdf_bates`:
    - High starting number (`--start 999999 --prefix LEGAL`).
    - High padding digit count (`padding: 8`).
18. `pdf_page_numbers`:
    - Position boundaries: `top-left`, `top-right`, `bottom-center`, `bottom-right`.
19. `pdf_annotate`:
    - Overlapping annotation rects and unicode text contents.
20. `pdf_read_form`:
    - Reading PDF with zero AcroForm fields -> Returns empty object `{}` cleanly without error or crash.
21. `pdf_fill_form`:
    - Filling non-existent field name -> Ignored or clean warning, no crash.

22. `pdf_flatten`:
    - Flattening document with zero forms -> Clean output PDF preserving visual appearance.
23. `pdf_create_form_field`:

## Technical Constraints & Safety Rules
1. **Zero Panic Rule**: Any unexpected panic or segfault fails the suite.
2. **Real Assertions Only**: No mock overrides (`if !passed { passed = true }` is strictly prohibited).
3. **Makefile Integration**:
   - Ensure `Makefile` has the `test-penta-edge-cases` recipe configured:
     ```makefile
     test-penta-edge-cases:
     	cargo run -p penta-interface-e2e -- --group edge_cases
     ```
   - Running `make test-penta-edge-cases` must successfully execute the suite.
4. **Execution & Report Output**:
   ```bash
   cargo run -p penta-interface-e2e -- --group edge_cases
   # or:
   make test-penta-edge-cases
   ```
   The suite must generate `reports/PENTA_INTERFACE_E2E_EDGE_CASES_REPORT.md` capturing every tool, interface, parameter permutation, assertion checked, and verdict.
