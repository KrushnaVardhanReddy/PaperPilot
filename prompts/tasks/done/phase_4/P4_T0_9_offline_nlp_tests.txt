Hey Jules! With the `OfflineNlpResolver` completely wired up, we need a rigorous test suite to ensure our heuristic rule engine and regex entity extractor actually produce the correct `OperationPlan` for real-world user commands.

## What to Build

Create an integration test file at `paperpilot-nlp/tests/resolver_accuracy_test.rs`.

### 1. The Dataset
In the test file, define an array or vector of test cases. Each test case should include:
- The natural language query string
- The expected `Intent`
- (Optional but recommended) Expected file counts or specific parameters.

Example cases to include:
- "Please merge document A.pdf and B.pdf into output.pdf" (Intent::Merge)
- "Extract pages 1-5 from my_file.pdf" (Intent::Extract, pages: "1-5")
- "Rotate this scanned.pdf by 90 degrees" (Intent::Rotate, angle: 90)
- "Compress financial_report.pdf" (Intent::Compress)
- "Add a password to secret.pdf. password is '12345'" (Intent::Encrypt, passwords: "12345")
- "Remove pages 2,4,6 from draft.pdf" (Intent::Delete)
- "Convert image.png to PDF" (Intent::ImageToPdf)
- "split large_book.pdf" (Intent::Split)
- "Add a watermark to confidential.pdf" (Intent::Watermark)
- "Redact sensitive info from contract.pdf" (Intent::Redact)

Create at least 25-30 diverse commands covering various intents and phrasings.

### 2. The Test Runner
Write a test `#[test] fn test_offline_resolver_accuracy()` that iterates over your dataset, feeds each string into `OfflineNlpResolver::new().resolve(query)`, and asserts that the `Result` is `Ok` and the `intent` matches the expectation.

### 3. Edge Cases (Negative Testing)
Add another test `#[test] fn test_offline_resolver_failures()` to verify that ambiguous or incomplete commands correctly return `NlpError`:
- "make the font bigger" -> `Err(AmbiguousIntent)`
- "rotate" (missing angle and file) -> `Err(MissingParameters)`
- "merge" (missing files) -> `Err(MissingParameters)`

## Rules & Constraints
1. Only touch `paperpilot-nlp/tests/`.
2. Do not modify the existing source code in `src/`. If a test fails because our regex/matcher isn't good enough, you can make a *tiny* fix in `entities.rs` or `intent.rs` aliases, but try to avoid major refactors.
3. Make sure `cargo clippy --workspace` passes with 0 warnings.
4. Make sure `cargo test -p paperpilot-nlp` passes.
