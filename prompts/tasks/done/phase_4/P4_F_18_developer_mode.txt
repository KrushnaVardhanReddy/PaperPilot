## CONTEXT & OBJECTIVE

PaperPilot offers free, unlimited offline processing that competes with Stirling PDF. To enable instant local automation (via Python, curl, n8n, homelabs) and developer adoption without requiring Docker or manual CLI commands, PaperPilot needs a built-in **Developer Mode**.

When Developer Mode is enabled:
1. The Desktop backend spawns/manages the `paperpilot-gateway` REST server locally on port 7823 (`http://127.0.0.1:7823`).
2. Developers can browse `http://127.0.0.1:7823/swagger-ui` in their browser or explore the integrated "API & Gateway" tab (`ApiDocsView.svelte`).
3. When toggled off or when the desktop application closes, the process/server terminates cleanly and frees port 7823.

File: `apps/desktop/src-tauri/src/lib.rs`
1. Define a global thread-safe state for the gateway server handle / cancellation token:
```rust
lazy_static::lazy_static! {
    static ref GATEWAY_RUNNING: Arc<Mutex<bool>> = Arc::new(Mutex::new(false));
    static ref GATEWAY_SHUTDOWN_TX: Arc<Mutex<Option<tokio::sync::oneshot::Sender<()>>>> = Arc::new(Mutex::new(None));
}
```

2. Implement Tauri commands:
- `get_gateway_status`: returns `{ is_running: bool, port: u16, swagger_url: String }`.
- `start_gateway`: if not running, binds to `127.0.0.1:7823`, starts the gateway server using `tokio::spawn`, sets state to running, and stores the shutdown sender.
- `stop_gateway`: if running, sends the shutdown signal, sets state to false, and releases port.

3. In `tauri::Builder::default()`:
Register the commands in `invoke_handler`:
`tauri::generate_handler![greet, invoke_mcp_tool, cancel_job, save_annotations, read_file_bytes, get_file_metadata, get_gateway_status, start_gateway, stop_gateway]`

4. On application exit/cleanup:
Ensure when the app window/process exits, `stop_gateway` is executed to clean up port 7823.

5. Add unit tests in `src-tauri/src/lib.rs` verifying status reporting and start/stop behavior.
