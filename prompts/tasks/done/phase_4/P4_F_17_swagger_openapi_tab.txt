## CONTEXT & GOAL

PaperPilot exposes a comprehensive REST API and MCP endpoints via `paperpilot-gateway` (running locally on port 7823 by default, or remotely).
The complete OpenAPI specification is located at:
`docs/api/openapi.json`

Currently, desktop users have no visual way within the desktop application to:
1. Explore the available API endpoints and operations schemas.
2. Inspect request parameters, payloads, responses, and curl commands.
3. Check the status of the local gateway server (`http://127.0.0.1:7823/health`).
4. Interactively execute requests against the gateway or copy ready-to-run curl snippets.

### Objective:
1. Create a dedicated **API / Gateway Documentation** view in the desktop app:
   `apps/desktop/src/lib/components/layout/ApiDocsView.svelte`
2. Bundle or load the OpenAPI specification cleanly in the desktop client.
3. Build a clean, responsive, dark-mode native OpenAPI / Swagger documentation browser matching PaperPilot's styling (custom cards by category, endpoints list with method tags [GET/POST], parameter tables, JSON body schemas, "Try It Out / Test" execution with curl code generation, and Gateway health check ping).
4. Integrate the new view into:
   - `apps/desktop/src/lib/state/app.svelte.ts` (allow `'api'` as an active tab)
   - `apps/desktop/src/lib/components/layout/Sidebar.svelte` (add the API navigation button with icon `⚡`)
   - `apps/desktop/src/routes/+page.svelte` (render `ApiDocsView` when `appState.activeTab === 'api'`)
5. Add unit tests for the new component and state in `apps/desktop/src/lib/components/layout/ApiDocsView.test.ts`.

### STEP 3: Create ApiDocsView.svelte
File: `apps/desktop/src/lib/components/layout/ApiDocsView.svelte`

Create a comprehensive, stylish API and Swagger viewer component:
- **Header Section:**
  - Title: "PaperPilot API & Gateway"
  - Gateway status badge (pings `http://127.0.0.1:7823/health` with a "Check Status" button, showing Online / Offline status and latency).
  - Target Base URL input (`id="api-gateway-url"`, defaulting to `http://127.0.0.1:7823`).
  - Search input (`id="api-search-input"`) to filter endpoints by tag, path, or description.
- **Category Filter Pills:**
  - All, Document, Operations, Security, MCP, Health
- **Endpoint Cards:**
  - Method badge (`GET` in blue, `POST` in emerald, `DELETE` in rose).
  - Endpoint path and summary/description.
  - Expandable detail view containing:
    - Request Body Schema / Parameters.
    - Example payload with "Copy Payload" button.
    - Generated `curl` command with "Copy cURL" button (`id="copy-curl-[endpoint-id]"`).
    - "Send Request" button (`id="send-request-[endpoint-id]"`) that makes a fetch request to the configured Base URL and displays the formatted JSON response and status code.
- **Embed / Spec Access:**
  - Button to view/download raw `openapi.json` (`id="btn-view-openapi-json"`).

Styles must use Vanilla CSS (dark theme, CSS variables such as `var(--bg-primary, #0f172a)`, `var(--text-primary, #f8fafc)`, `var(--accent-color, #38bdf8)`, rounded cards, smooth transitions).
