## All Required Fixes

### Fix A: `pdf_rotate` — make `pages` optional in MCP/API
**Error:** `"Missing or invalid 'pages' parameter"`  
**Context:** The gateway's `handle_tool` dispatches `pdf_rotate` and tries to extract a `pages` field. Callers only send `angle` or `degrees`.

In `handlers.rs`, find the `pdf_rotate` dispatch block. Change the `pages` extraction to use `.get("pages").and_then(...)` with a fallback:

```rust
// Instead of requiring pages:
let pages = params.get("pages")
    .and_then(|v| v.as_str())
    .unwrap_or("all")   // default: rotate all pages
    .to_string();

// Accept both "angle" and "degrees" keys:
let degrees = params.get("degrees")
    .or_else(|| params.get("angle"))
    .and_then(|v| v.as_i64())
    .ok_or_else(|| /* missing degrees error */)? as i32;
```

### Fix B: `pdf_crop` — accept `x, y, width, height` OR `box` parameter
**Error:** `"Missing or invalid 'box' parameter"`  
**Context:** MCP/API callers send `{"x": 10, "y": 10, "width": 500, "height": 700}` but the handler expects a `box` parameter.

In `handlers.rs`, find the `pdf_crop` dispatch block and normalize:
```rust
// Accept either "box" string or individual x/y/width/height fields:
let crop_rect = if let Some(box_param) = params.get("box") {
    box_param.as_str().unwrap_or("").to_string()
} else {
    let x = params.get("x").and_then(|v| v.as_f64()).unwrap_or(0.0);
    let y = params.get("y").and_then(|v| v.as_f64()).unwrap_or(0.0);
    let w = params.get("width").and_then(|v| v.as_f64()).unwrap_or(0.0);
    let h = params.get("height").and_then(|v| v.as_f64()).unwrap_or(0.0);
    format!("{},{},{},{}", x, y, w, h)
};

// Also make "pages" optional, defaulting to "all":
let pages = params.get("pages").and_then(|v| v.as_str()).unwrap_or("all").to_string();
```

### Fix D: `pdf_burst` — create output directory before operation
**Error:** `"I/O error: No such file or directory (os error 2)"`  
**Context:** The `pdf_burst` tool receives an `output_dir` path that doesn't exist yet. The operation fails trying to write burst files into a non-existent directory.

In `handlers.rs`, find the `pdf_burst` dispatch block and add directory creation:
```rust
let output_dir_path = std::path::Path::new(&output_dir);
if !output_dir_path.exists() {
    std::fs::create_dir_all(output_dir_path)
        .map_err(|e| format!("I/O error: {}", e))?;
}
```

Do this before calling the underlying operation.

### Fix E: `pdf_reorder_pages` — fix parameter name (MCP sends `order`, handler may expect different name)
**Error:** `"Parse error: New order length (3) must match document page count (5)"`  
**Context:** This error actually comes from the `paperpilot-pdf` core crate (not the gateway). BUT the gateway CAN help by passing the page count to the operation and truncating/extending the order list.

In `handlers.rs`, for the `pdf_reorder_pages` dispatch:
1. After parsing `order` as a Vec<usize>, get the document page count.
2. If `order.len() < page_count`, extend the order list by appending remaining page numbers in original order:
   ```rust
   let mut full_order = order.clone();
   let already_listed: std::collections::HashSet<usize> = order.iter().cloned().collect();
   for page in 1..=page_count {
       if !already_listed.contains(&page) {
           full_order.push(page);
       }
   }
   ```
3. Pass `full_order` to the operation instead of the raw `order`.

To get `page_count`, load the PDF using `paperpilot_pdf` before calling the operation. Check what utility function is available (e.g., `paperpilot_pdf::utils::get_page_count(path)` or open via `lopdf::Document`).
