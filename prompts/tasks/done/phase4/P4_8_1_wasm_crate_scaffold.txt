# Task: Phase 4.8.1 — `paperpilot-wasm` Complete Client-Side Engine & Web Worker Bridge

## Objective
Implement Task 4.8.1: Create the new `paperpilot-wasm` crate in the PaperPilot Cargo workspace and provide a complete client-side WebAssembly execution engine. Expose 6 core PDF operations (`merge`, `rotate`, `split`, `compress`, `encrypt`, `watermark`) to WebAssembly (`wasm32-unknown-unknown`) using `wasm-bindgen`. All operations must execute strictly in memory on `Uint8Array` / byte buffers with zero filesystem calls. Provide an off-main-thread Web Worker bridge (`pdfWorker.ts`) in `apps/desktop/src/lib/wasm/` for non-blocking browser UI dispatch.

## Technical Requirements

### 1. Workspace Registration (`Cargo.toml`)
- Add `"paperpilot-wasm"` to the root `[workspace]` `members` list.

### 2. Crate Configuration (`paperpilot-wasm/Cargo.toml`)
- `[package]` name: `"paperpilot-wasm"`, version: `"0.1.0"`, edition: `"2024"`.
- `[lib]` crate-type: `["cdylib", "rlib"]`.
- Dependencies:
  - `wasm-bindgen = "0.2"`
  - `js-sys = "0.3"`
  - `lopdf = { version = "0.35.0", default-features = false }` (or matching workspace lopdf version)
  - `paperpilot-core = { path = "../paperpilot-core" }`
- Note: Keep dependencies pure Rust with zero C/C++ runtime bindings so that compilation to `wasm32-unknown-unknown` succeeds cleanly.

### 3. In-Memory Wasm Engine API (`paperpilot-wasm/src/lib.rs` & `src/operations.rs`)
Implement the `WasmPdfEngine` struct exported via `#[wasm_bindgen]`:

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub struct WasmPdfEngine;

#[wasm_bindgen]
impl WasmPdfEngine {
    /// Merge multiple PDF buffers (Array of Uint8Array) into a single PDF Uint8Array
    #[wasm_bindgen]
    pub fn merge(buffers: js_sys::Array) -> Result<js_sys::Uint8Array, JsValue>;

    /// Rotate specific pages ("all", "1,2", or "1") by angle (90, 180, 270)
    #[wasm_bindgen]
    pub fn rotate(input_bytes: &[u8], angle: u16, pages: &str) -> Result<js_sys::Uint8Array, JsValue>;

    /// Split PDF by page ranges (e.g. "1-2, 3-4") returning an Array of Uint8Arrays
    #[wasm_bindgen]
    pub fn split(input_bytes: &[u8], ranges: &str) -> Result<js_sys::Array, JsValue>;

    /// Compress PDF by removing unneeded metadata, deflating streams, and cleaning cross-references
    #[wasm_bindgen]
    pub fn compress(input_bytes: &[u8]) -> Result<js_sys::Uint8Array, JsValue>;

    /// Encrypt PDF with user password (standard 128/256-bit)
    #[wasm_bindgen]
    pub fn encrypt(input_bytes: &[u8], password: &str) -> Result<js_sys::Uint8Array, JsValue>;

    /// Add watermark text across pages
    #[wasm_bindgen]
    pub fn watermark(input_bytes: &[u8], text: &str) -> Result<js_sys::Uint8Array, JsValue>;
}
```

### 4. Zero Filesystem Footprint (Pure Memory Streams)
- Strictly avoid `std::fs::*` and `tempfile`.
- Load and parse documents directly using `lopdf::Document::load_mem(input_bytes)` or `load_from(input_bytes)`.
- Save output into a `Vec<u8>` in-memory buffer (`doc.save_to(&mut buffer)`), converting back to `js_sys::Uint8Array::from(&buffer[..])`.
- Return errors converted to `JsValue::from_str(&format!("{e}"))`.

### 5. Web Worker Bridge (`apps/desktop/src/lib/wasm/pdfWorker.ts` & `index.ts`)
Provide a clean Web Worker interface for background execution:
- `pdfWorker.ts`: Listens for messages `{ id, type, payload }`, invokes `WasmPdfEngine` methods, and posts back `{ id, success, result, error }`.
- `index.ts`: Exposes a typed async client:
  ```typescript
  export interface WasmPdfClient {
    merge(files: Uint8Array[]): Promise<Uint8Array>;
    rotate(file: Uint8Array, angle: number, pages?: string): Promise<Uint8Array>;
    split(file: Uint8Array, ranges: string): Promise<Uint8Array[]>;
    compress(file: Uint8Array): Promise<Uint8Array>;
    encrypt(file: Uint8Array, password: string): Promise<Uint8Array>;
    watermark(file: Uint8Array, text: string): Promise<Uint8Array>;
  }
  ```
