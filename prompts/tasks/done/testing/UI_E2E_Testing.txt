## Step 1: Generate Fresh Test Fixtures

Before running any UI test, programmatically generate fresh PDF fixtures. Use a Python script or the `paperpilot-cli` binary:
- `tests/e2e_fixtures/single_page.pdf` — 1 page, text content
- `tests/e2e_fixtures/multi_page.pdf` — 5 pages, text content
- `tests/e2e_fixtures/image_doc.pdf` — 3 pages with embedded images

These freshly generated files must be used as inputs throughout the UI test workflow.

First, ensure Playwright is installed and configured in `apps/desktop/`. If not, set it up using:
```bash

npx playwright install
```

## Step 3: Generate `UI_TEST_REPORT.md`

After running `npx playwright test`, read the test results and generate `reports/UI_TEST_REPORT.md`:

```markdown
# PaperPilot Desktop UI — E2E Test Report
Generated: <timestamp>
Playwright Version: <version>
App Version: <from package.json>

## Summary
- Total Tests: X
- Passed: X ✅
- Failed: X ❌

## Detailed Results

### ✅ Working Flows
| Test | Duration | Notes |

### ❌ Failed Tests
| Test | Error Message | Screenshot Path | Root Cause (file:line if found) |

### A11y / Responsiveness Issues
List any elements that overflow, are unreachable via keyboard, or have missing ARIA roles.

### Tauri IPC Issues
List any `invoke()` calls that returned an error, with the full error payload.

### Visual Regressions
If any Playwright screenshots were captured showing unexpected UI state, list them here.
```
