## Step 1: Fixture Setup

Programmatically generate the following real PDF fixtures in `tests/e2e_fixtures/` (add to `.gitignore`). Use `paperpilot-cli create`, `lopdf`, or `printpdf` directly:

| Fixture | Description |
|---|---|

---

## Step 2: Build the Test Script

Write a bash script at `scripts/test_cli_e2e.sh`. It must:
1. Build the `paperpilot-cli` binary first: `cargo build --release -p paperpilot-cli`
2. Define a helper function `run_test` that:
   - Executes the command
   - Captures stdout, stderr and the exit code
   - If exit code is non-zero OR the expected output file does not exist → marks the test **FAILED**
   - Otherwise → marks it **PASSED**
3. After all tests finish, print a summary: total tests, passed, failed.
4. Exit with code `1` if ANY test failed, so CI can detect failures.

## Step 4: Error Condition Tests

Test how the CLI handles bad inputs (all should exit with non-zero code and a human-readable error message):
- `merge` with a non-existent file path → must not panic, must print useful error
- `decrypt` with wrong password → must exit with clear error message
- `rotate` with invalid angle `--angle 45` → must print validation error
- Any command with `--output /nonexistent/dir/output.pdf` → must print permission error
