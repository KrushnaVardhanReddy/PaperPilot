Jules, you are our Senior Autonomous QA Engineer.
Your mission is to:
1. Generate a test document **using PaperPilot's conversion engine** containing numbered contracts and bullet points.

```bash

cargo run -p paperpilot-cli -- convert --format pdf --input /tmp/contract_numbered.md --output tests/e2e_fixtures/contract_555.pdf --css-preset corporate
```

## STEP 2: LAUNCH & TEST VIA AGENT BROWSER

1. Start dev server:
   ```bash
   npm --prefix apps/desktop run dev &
   sleep 3
   ```

2. Open app and load `tests/e2e_fixtures/contract_555.pdf`:
   ```bash
   npx --prefix apps/desktop agent-browser open "http://localhost:5173"
   npx --prefix apps/desktop agent-browser snapshot -i
   ```

3. **Verify Annotation Tools in Top Toolbar**:
   - Check presence of exact button elements:
     - `#tool-btn-none` (Pointer)
     - `#tool-btn-highlight` (Highlight)
     - `#tool-btn-underline` (Underline)
     - `#tool-btn-strikethrough` (Strike)
     - `#tool-btn-pen` (Pen)
     - `#tool-btn-note` (Note)

4. **Test Pointer Tool (Default Active)**:
   - Verify `#tool-btn-none` has the `.active` class on initial load.

5. **Test Note Tool**:
   - Click `#tool-btn-note`:
     ```bash
     npx --prefix apps/desktop agent-browser click "#tool-btn-note"
     ```
   - Verify `#tool-btn-note` gets the `.active` class and `#tool-btn-none` loses `.active`.

6. **Test Highlight, Underline, and Pen Tools**:
   - Click `#tool-btn-highlight` -> verify active.
   - Click `#tool-btn-underline` -> verify active.
   - Click `#tool-btn-strikethrough` -> verify active.
   - Click `#tool-btn-pen` -> verify active.
   - Click back on `#tool-btn-none` (Pointer) -> verify it returns to active pointer mode.

7. **Verify Annotation Canvas & Right Drawer**:
   - Ensure the right sidebar tab `Annotations (0)` is present and clickable.
   - Verify no toolbar buttons overlap on the PDF viewer canvas.

8. **Triple-Channel Verification Contract (UI vs. REST vs. MCP)**:

| Channel | Input Payload / Action | Expected Output | Assertion Command |
|---|---|---|---|
| **Channel 1 (UI)** | Click `#tool-btn-highlight` + drag over heading | Highlight markup SVG element created on canvas | `.annotation-layer rect` or `.annotation-layer mark` exists |
| **Channel 2 (REST)** | `POST /api/v1/pdf/watermark` (`text="CONFIDENTIAL #555"`) | `HTTP 200` + `application/pdf` binary stream | `curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/watermark -F "file=@tests/e2e_fixtures/contract_555.pdf" -F "text=CONFIDENTIAL #555" -o /tmp/watermarked_api.pdf && test -s /tmp/watermarked_api.pdf` |
| **Channel 2 (REST)** | `POST /api/v1/pdf/tools/watermark` | `HTTP 200` + JSON with output path | `curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/tools/watermark -H "Content-Type: application/json" -d '{"input":"tests/e2e_fixtures/contract_555.pdf","text":"CONFIDENTIAL #555","output":"/tmp/watermarked_tools.pdf"}' \| grep -i 'success'` |
| **Channel 3 (MCP SSE)** | `POST /mcp/messages` (`pdf_watermark`) | `HTTP 200` + JSON-RPC result | `curl -s -X POST "http://127.0.0.1:7823/mcp/messages?sessionId=qa5-test" -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pdf_watermark","arguments":{"input":"tests/e2e_fixtures/contract_555.pdf","text":"CONFIDENTIAL #555","output":"/tmp/watermarked_mcp.pdf"}}}' \| grep -i 'result'` |

- **Strict Parity Rule**: Visual stamps and watermarks placed via UI must match the exact stamp layer and file size growth produced by REST and MCP watermarking endpoints.
