## 🎯 MISSION OBJECTIVE

Jules, you are our Senior Autonomous QA Engineer.
Your mission is to:
1. Generate a multi-page test PDF **using PaperPilot's conversion engine** containing repeating numbered serial codes (e.g. `SERIAL-777` appearing on Page 1, Page 3, and Page 5).
2. Launch the desktop app and open the document.
3. Test canvas text search (`Ctrl+F`), searching for `SERIAL-777`, navigating matches (`1 of 3`, `2 of 3`, `3 of 3`), and closing search (`Esc`).
4. Verify search and text extraction parity headlessly via the REST API endpoint (`/api/v1/pdf/extract-text` & `/api/v1/pdf/search`).
5. If ANY search highlight, shortcut, or navigation defect is found, fix the code and submit a green PR.

## STEP 1: CREATE TEST PDF WITH SPECIFIC SEARCHABLE NUMBERS

```bash
cat << 'EOF' > /tmp/search_test_numbered.md

cargo run -p paperpilot-cli -- convert --format pdf --input /tmp/search_test_numbered.md --output tests/e2e_fixtures/search_test.pdf --css-preset minimal
```

## STEP 2: LAUNCH & TEST VIA AGENT BROWSER

1. Start dev server:
   ```bash
   npm --prefix apps/desktop run dev &
   sleep 3
   ```

2. Open app and load `tests/e2e_fixtures/search_test.pdf`:
   ```bash
   npx --prefix apps/desktop agent-browser open "http://localhost:5173"
   npx --prefix apps/desktop agent-browser snapshot -i
   ```

3. **Open Search Bar**:
   - Press shortcut `ControlOrMeta+f`:
     ```bash
     npx --prefix apps/desktop agent-browser keyboard press "ControlOrMeta+f"
     ```
   - Verify `#pdf-search-bar` is visible.

4. **Search for Numbered Target**:
   - Fill `#pdf-search-input` with `SERIAL-777` and press Enter.
   - Verify match indicator `#pdf-search-count` shows `1 of 3` (or `3 matches`).

5. **Navigate Matches**:
   - Click `#pdf-search-next` (Next button) -> verify counter advances to `2 of 3`.
   - Click `#pdf-search-prev` (Prev button) -> verify counter returns to `1 of 3`.

6. **Close Search**:
   - Click `#pdf-search-close` (or press Escape).
   - Verify `#pdf-search-bar` is hidden.

7. **Triple-Channel Verification: REST API & MCP Text Extraction**:
   - Ensure text search and extraction work consistently across all channels:
     ```bash
     # ── CHANNEL 2: REST API (Port 7823) ──
     # 1. Convenience Endpoint:
     curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/extract-text \
       -F "file=@tests/e2e_fixtures/search_test.pdf" \
       -F "query=SERIAL-777"

     # 2. Dynamic 44-Tool Router:
     curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/tools/extract_text \
       -H "Content-Type: application/json" \
       -d '{"input": "tests/e2e_fixtures/search_test.pdf", "output": "/tmp/extracted_search_text.txt"}'

     # ── CHANNEL 3: MCP PROTOCOL ──
     # 3. Search text via MCP stdio:
     echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pdf_search","arguments":{"input":"tests/e2e_fixtures/search_test.pdf","query":"SERIAL-777"}}}' | cargo run -p paperpilot-mcp
     ```
   - Assert all channels confirm the presence of matches across the pages.
