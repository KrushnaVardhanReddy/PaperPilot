## STEP 1: CREATE TEST DOCUMENTS USING PAPERPILOT'S CONVERSION ENGINE

Instead of using generic third-party files, create test PDFs **using our own Markdown → PDF converter** with distinct numbers so text and pages are identifiable:

Run these commands in terminal:
```bash
# Create Markdown document 1 with recognizable numbered sections
cat << 'EOF' > /tmp/doc_100_report.md
# Financial Report 100
- Invoice ID: #100-98765
- Account Balance: $100,500.00
- Total Transactions: 100
- Target Milestone: 100% Complete
EOF

# Create Markdown document 2 with recognizable numbered sections
cat << 'EOF' > /tmp/doc_200_analytics.md
# Analytics Summary 200
- Unique Visitors: 200,450
- Page Views: 200,990
- Conversion Ratio: 2.00%
- Servers Active: 200 Nodes
EOF

# Convert them to PDF using paperpilot-cli
cargo run -p paperpilot-cli -- convert --format pdf --input /tmp/doc_100_report.md --output tests/e2e_fixtures/doc_100.pdf --css-preset corporate
cargo run -p paperpilot-cli -- convert --format pdf --input /tmp/doc_200_analytics.md --output tests/e2e_fixtures/doc_200.pdf --css-preset academic
```

Verify both `tests/e2e_fixtures/doc_100.pdf` and `tests/e2e_fixtures/doc_200.pdf` exist.

## STEP 2: LAUNCH THE DEV SERVER & BROWSER EXPLORATION

1. Start the Vite dev server in the background:
   ```bash
   npm --prefix apps/desktop run dev &
   sleep 3
   ```

2. Open the page via `agent-browser`:
   ```bash
   npx --prefix apps/desktop agent-browser open "http://localhost:5173"
   npx --prefix apps/desktop agent-browser snapshot -i
   ```

---

## STEP 3: EXECUTE QA FLOWS VIA AGENT BROWSER

1. **Test Initial State**:
   - Inspect snapshot output. Ensure `.drop-zone` and `#tab-btn-home` are visible.
   - Verify dark mode contrast: background surface is dark, text is readable.

2. **Test Opening Multi-Documents**:
   - Load both `doc_100.pdf` and `doc_200.pdf` into the file input.
   - Run snapshot:
     ```bash
     npx --prefix apps/desktop agent-browser snapshot -i
     ```
   - **Assertion:** Verify that both tabs exist: `#tab-doc-0` (`doc_100.pdf`) and `#tab-doc-1` (`doc_200.pdf`).

3. **Test Switching Document Tabs**:
   - Click `#tab-doc-1`:
     ```bash
     npx --prefix apps/desktop agent-browser click "#tab-doc-1"
     ```
   - Verify that `#tab-doc-1` has the active tab styling.
   - Verify that the canvas renders the "Analytics Summary 200" content.

4. **Test Closing Tabs**:
   - Click `#tab-close-1` to close the second document:
     ```bash
     npx --prefix apps/desktop agent-browser click "#tab-close-1"
     ```
   - Verify `#tab-doc-1` is removed from the DOM and `#tab-doc-0` automatically becomes active.

5. **Dual-Channel Verification: REST API Document Inspection & Health**:
   - Ensure the server endpoint processes the exact same fixtures via HTTP:
     ```bash
     # Verify health
     curl -s http://127.0.0.1:7823/health
     # Inspect doc_100.pdf metadata headlessly
     curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/info \
       -F "file=@tests/e2e_fixtures/doc_100.pdf"
     # Inspect doc_200.pdf metadata headlessly
     curl -s -X POST http://127.0.0.1:7823/api/v1/pdf/info \
       -F "file=@tests/e2e_fixtures/doc_200.pdf"
     ```
   - Verify both HTTP responses return valid JSON with correct page counts.
