## Objective
Create the standalone `paperpilot-ai` crate in the root workspace implementing:
1. `UniversalLlmClient`: An async HTTP client using `reqwest` targeting ANY OpenAI-compatible `/v1/chat/completions` endpoint:
   - Configurable `endpoint_url` (e.g. `http://localhost:11434/v1` for Ollama, `http://127.0.0.1:8080/v1` for Llamafile, `https://api.groq.com/openai/v1`, `https://api.openai.com/v1`).
   - Configurable `model` name and optional `api_key`.
   - Native support for tool calling (`tools` array with JSON schema, `tool_choice: "auto"`).
2. `LlmNlpResolver`: Struct implementing the `NlpResolver` trait from `paperpilot-nlp::traits::NlpResolver`:
   - Converts natural language queries into an `OperationPlan` by invoking the LLM with PaperPilot tool definitions.
   - Parses LLM tool calls into strongly-typed `OperationPlan` structs.
3. `DynamicRouter`: Factory/router pattern that seamlessly swaps between `paperpilot_nlp::resolver::OfflineNlpResolver` (100% offline embedded model, 0.4ms) and `LlmNlpResolver` (local LLM / BYOK), with automatic fallback to offline NLP if the LLM endpoint is unreachable.

---

## ARCHITECTURAL CONTEXT: SINGLE CODEBASE, DYNAMIC RUNTIME SWITCHING
PaperPilot uses **ONE single codebase and ONE binary on `main`** — NEVER two Git branches or split binaries:
- The `paperpilot-nlp` crate provides the embedded `OfflineNlpResolver` (0-config, <1.1MB ONNX model, instant response).
- The `paperpilot-ai` crate provides the `LlmNlpResolver` (multi-step tool reasoning via Local Llamafile, Ollama, or BYOK).
- Both implement the exact same trait: `paperpilot_nlp::traits::NlpResolver`.
- The user can seamlessly toggle between "Offline NLP Mode" and "Local AI Agent / BYOK Mode" in application settings.
- If Local LLM is selected but the endpoint is offline or unavailable, the system automatically falls back to `OfflineNlpResolver` without crashing.

## 2. Implementation Specifications

### A. Universal OpenAI Client (`paperpilot-ai/src/client.rs`)
```rust
#[derive(Clone, Debug, serde::Serialize, serde::Deserialize)]
pub struct LlmConfig {
    pub endpoint_url: String, // e.g. "http://localhost:11434/v1" or "http://127.0.0.1:8080/v1"
    pub model: String,        // e.g. "llama-3.2-3b-instruct" or "qwen2.5-coder:7b"
    pub api_key: Option<String>,
    pub temperature: Option<f32>,
}

pub struct UniversalLlmClient {
    config: LlmConfig,
    http: reqwest::Client,
}
```
- Implement `pub async fn chat_completion(&self, messages: Vec<ChatMessage>, tools: Option<Vec<ToolDefinition>>) -> Result<ChatCompletionResponse, AiError>`.
- Sends `POST {endpoint_url}/chat/completions`.
- Adds `Authorization: Bearer {api_key}` header only if `api_key` is present and non-empty.

### B. LLM Resolver (`paperpilot-ai/src/resolver.rs`)
- Implements `paperpilot_nlp::traits::NlpResolver for LlmNlpResolver`.
- Formulates system prompt specifying available PDF operations (`merge`, `split`, `rotate`, `redact`, `bates`, `compress`, `encrypt`, `watermark`, etc.).
- When `resolve_with_context(query, context)` is called:
  - Formulates user query and context (active document, open documents).
  - Calls `UniversalLlmClient::chat_completion`.
  - Maps tool calls from the model response into `OperationPlan { intent, input_files, output_file, page_ranges, angles, passwords, raw_query }`.
  - Fallbacks gracefully to `NlpError::AmbiguousIntent` if model fails to pick a tool.
