# Task 5.9.90 Prompt: Baseline Integrity & Pre-Sign Tamper Detection (`pdf_validate_signatures --baseline`)

You are implementing Task 5.9.90 (Spec 101): Extending `pdf_validate_signatures` to support `--baseline` integrity checks in PaperPilot.

### Context & Goal
Digital signature verification checks if a document is cryptographically valid and whether it was modified *after* signing. But when an enterprise or user issues a contract (such as a commercial credit card or loan agreement), they also need to know:
**"Did the recipient modify any numbers, rates, or clauses BEFORE applying their signature?"**

Your job is to enhance `pdf_validate_signatures` across the Rust engine and interfaces to accept an optional baseline document, compare the structural content and text streams, and produce a unified validation + baseline report.

### Step 1: Data Structures (`paperpilot-pdf/src/operations/pdf_validate_signatures.rs`)

Update the options and report structs:

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct PdfValidateSignaturesOptions {
    /// Optional path to baseline reference PDF
    #[serde(default)]
    pub baseline_path: Option<String>,
    /// Optional raw bytes of baseline reference PDF
    #[serde(default)]
    pub baseline_bytes: Option<Vec<u8>>,
    /// If true, verify byte range only
    #[serde(default)]
    pub verify_byte_range_only: bool,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct BaselineComparisonReport {
    pub baseline_checked: bool,
    pub baseline_match: bool,
    pub verdict: String, // "UNTOUCHED_JUST_SIGNED" | "CONTENT_ALTERED_PRIOR_TO_SIGNATURE"
    pub altered_pages: Vec<u32>,
    pub diff_summary: Vec<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SignatureValidationReport {
    pub total_signatures: usize,
    pub valid_signatures: usize,
    pub all_valid: bool,
    pub signatures: Vec<DigitalSignatureInfo>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub baseline_report: Option<BaselineComparisonReport>,
}
```

### Step 2: Implementation Logic in `pdf_validate_signatures_bytes`

1. Read baseline bytes from `options.baseline_bytes` or `options.baseline_path` (if provided).
2. If baseline bytes are present:
   - Load both `doc` (input) and `baseline_doc` (baseline).
   - Compare page counts:
     - If count differs, return `baseline_match: false`, `verdict: "CONTENT_ALTERED_PRIOR_TO_SIGNATURE"`, `diff_summary: ["Page count mismatch: baseline has X pages, signed file has Y pages"]`.
   - For each page index (1..=page_count):
     - Extract raw text streams from baseline page `/Contents` and signed page `/Contents`.
     - Filter out signature widget appearances (marked with `/Subtype /Widget` and `/FT /Sig`).
     - Compare normalized page text. If differences exist:
       - Record page number in `altered_pages`.
       - Add concise description of difference to `diff_summary` (e.g. `"Page 1 text mismatch: altered clauses or numbers detected"`).
   - If `altered_pages` is empty:
     - Set `baseline_match: true`, `verdict: "UNTOUCHED_JUST_SIGNED"`.
   - Else:
     - Set `baseline_match: false`, `verdict: "CONTENT_ALTERED_PRIOR_TO_SIGNATURE"`.
3. Include `baseline_report` in `SignatureValidationReport`.
