## Objective
Build and execute a **100% pure-Rust, zero-Python Tri-Interface E2E Test Suite** in `tools/tri-interface-e2e/`.

This crate must execute **independent, rigorous 3rd-party semantic assertions** across all 44 tools and all 3 developer interfaces:
1. **💻 CLI**: invoking `target/debug/paperpilot-cli` (or release) subprocess.
2. **🤖 MCP**: stdio JSON-RPC 2.0 communication with `target/debug/paperpilot-mcp`.
3. **🌐 REST API**: spawning `paperpilot serve --port 7823` in background, polling `/health` until ready, and sending HTTP requests to the REST endpoints.

Every tool must be tested across **3 positive complexity tiers** (Simple, Medium, Complex/Hard) plus a **negative test case**, asserting exact page content, structure, and metadata without any lazy shortcuts.

## 2. Global Semantic Verification Rules

1. **Input Immutability**:
   - Before any test executes, compute SHA-256 of all input fixtures.
   - After the test completes, verify all input files retain their exact original hash.
2. **Output Non-Identity**:
   - For tools producing a new document (merge, split, rotate, watermark, encrypt, etc.), verify the output SHA-256 does NOT match any input file's SHA-256.
   - **Crucial Rule**: ONLY compare the output hash against actual INPUT files. Do NOT hash the output destination path beforehand!
3. **Gateway Server Lifecycle**:
   - Spawn `paperpilot serve --port 7823`.
   - Poll `http://127.0.0.1:7823/health` with exponential backoff / retry up to 15 seconds until HTTP 200 is received before invoking any REST endpoint.
   - Cleanly terminate the gateway child process upon test suite completion.

## 3. Four-Case Matrix Per Tool (Simple, Medium, Complex, Negative)

Every one of the 44 tools must define and execute 4 cases:
1. **Tier 1 (Simple)**: Minimal valid input (e.g. 1-2 pages, simple text, basic operation).
2. **Tier 2 (Medium)**: Multi-page document with structured layout (e.g. 5-page document, custom page ranges like `"1,3"`, rotation `90`, custom output paths).
3. **Tier 3 (Complex / Hard)**: Real-world complex stress documents (e.g. multi-column invoice with tables, multi-file batch merges with 3+ files, documents with accented/unicode strings, boundary conditions like processing the last page of a multi-page doc).
4. **Negative Test Case**: Intentionally invalid input (e.g. missing input file, invalid page range `"99"`, wrong password) asserting a non-zero exit code or error JSON response.

## 4. Specific Semantic Assertions Per Tool Category

### A. Page Operations (9 Tools)
1. `pdf_merge`:
   - **Simple**: Merge `merge_a.pdf` ("AAA") + `merge_b.pdf` ("BBB"). Assert 2 pages. Page 1 contains "AAA", Page 2 contains "BBB".
   - **Medium**: Merge `merge_a.pdf` ("AAA") + `multi_page.pdf` (5p). Assert 6 pages, P1="AAA", P2..P6="PAGE_TEXT_P1"..P5.
   - **Complex**: Merge 3 files: `merge_a.pdf` + `merge_b.pdf` + `merge_c.pdf`. Assert 3 pages, P1="AAA", P2="BBB", P3="CCC".
   - **Negative**: Missing input file -> non-zero exit code or error JSON.
2. `pdf_split`:
   - Assert exact page text matches the requested range (e.g. `"1,2"` produces 2 pages with `"PAGE_TEXT_P1"` and `"PAGE_TEXT_P2"`; `"PAGE_TEXT_P3"` is NOT present).
3. `pdf_extract_pages`: Assert page count and text match extracted pages only.
4. `pdf_delete_pages`: Assert deleted pages are absent from output.
5. `pdf_reorder_pages`: Assert page sequence matches requested permutation `[2, 1, 3, 4, 5]`.
6. `pdf_rotate`: Inspect `/Rotate` integer in page dictionary using `lopdf`. Verify it equals the requested angle (e.g. 90, 180).
7. `pdf_crop`: Inspect `MediaBox` or `CropBox` coordinates in `lopdf`.
8. `pdf_burst`: Assert output directory contains exactly N single-page files, each containing its respective page text.
9. `pdf_remove_blank`: Assert blank pages are removed while content pages are preserved in order.

### B. Optimization & Repair (3 Tools)
10. `pdf_compress`: Assert output size <= input size; text intact.
11. `pdf_repair`: Repaired corrupt PDF loads successfully in `lopdf`.
12. `pdf_linearize`: Output contains `/Linearized` object dictionary.

### C. Security (5 Tools)
13. `pdf_encrypt`: Opening without password fails or contains `/Encrypt`; opening with password succeeds.
14. `pdf_decrypt`: Decrypted file opens with no password; `/Encrypt` absent.
15. `pdf_redact`: Target secret text (`"SECRET 12345"`) is completely absent from all content streams; non-redacted text preserved.
16. `pdf_sign`: Output contains `/Sig` or `/ByteRange`.
17. `pdf_hash`: Computed hash matches SHA-256 of file bytes.

### D. Stamping & Numbering (5 Tools)
18. `pdf_watermark`: Watermark text appears on every page; original text preserved.
19. `pdf_header_footer`: Header text at top, footer text at bottom verified.
20. `pdf_bates`: Sequential Bates numbers (e.g. `BATES-000001` through `BATES-000005`) present in order.
21. `pdf_page_numbers`: Formatted page numbers (e.g. `"1/5"`, `"5/5"`) present.
22. `pdf_annotate`: Annotation dictionary `/Annots` contains expected comment/annotation.

### E. Forms (4 Tools)
23. `pdf_read_form`: Returns form field names and values in JSON.
24. `pdf_fill_form`: Re-reading output confirms updated field value.
25. `pdf_flatten`: Form fields removed from interactive dictionary, rendered into page stream.
26. `pdf_create_form_field`: New form field exists in `/AcroForm` `/Fields`.

### F. Extraction & Analysis (10 Tools)
27. `pdf_extract_text`: Extracted text contains expected keywords (`"Invoice 4821"`, `"Total $1,250.00"`).
28. `pdf_extract_images`: Extracted image files load successfully and have valid dimensions.
29. `pdf_search`: Query matches exact page index.
30. `pdf_render`: Rendered PNG has valid PNG header, dimensions > 0, size > 5KB.
31. `pdf_compare`: Identifies text differences between two documents.
32. `pdf_metadata`: Returns valid page count and metadata fields.
33. `pdf_bookmarks`: Returns outline/bookmarks hierarchy.
34. `pdf_classify_type`: Correctly classifies text-based vs image-based PDF.
35. `pdf_validate`: Returns valid status.
36. `pdf_ocr`: Output PDF has searchable text layer.

### G. Conversions (8 Tools)
37. `pdf_images_to_pdf`: Image converted into valid 1-page PDF.
38. `pdf_to_pdf_a`: Output conforms to PDF/A metadata.
39. `pdf_to_docx`: Output `.docx` is a valid zip containing `word/document.xml` with text.
40. `pdf_to_xlsx`: Output `.xlsx` is a valid zip containing `xl/worksheets/sheet1.xml` with cells.
41. `pdf_to_pptx`: Output `.pptx` is a valid zip containing `ppt/slides/slide1.xml`.
42. `pdf_convert_html`: Converted HTML produces PDF containing HTML text.
43. `pdf_convert_markdown`: Converted Markdown produces PDF containing Markdown text.
44. `pdf_convert_excel`: Converted CSV/XLSX produces PDF containing tabular data.
