Task: Penta-Interface In-Memory WASM Parity & Sandboxed E2E Hardening [Spec 057]

Context:
The 5-Interface E2E suite (`tools/penta-interface-e2e`) has reached a 100% pass baseline across 1,041 tests. However, several WASM and Cloudflare Edge columns currently use simulated marker assertions (`[Simulated] WasmEngine call`). In addition, repeated test runs write to a shared output directory (`tests/e2e_fixtures/out/`), introducing the potential for stale-cache passes.

This task hardens the E2E suite by establishing true in-memory buffer execution for WASM/Edge, wiping test output sandboxes before runs, and expanding semantic validations in the Playwright suite.

CRITICAL CONSTRAINTS:
1. ZERO HARDCODED MOCKS: No dummy `passed: true` without asserting actual returned data/bytes.
2. WORKSPACE SAFETY: NEVER execute `git reset`, `git checkout -- .`, `git clean -fd`, or `git restore`.
3. CONCURRENCY: Maintain bounded concurrency (`-j 4`).

================================================================================
PART 1: SANDBOXED TEST RUN ISOLATION
================================================================================
In `tools/penta-interface-e2e/src/main.rs`:
1. Before running test suites, ensure the test output directory (`tests/e2e_fixtures/out/penta_e2e`) is cleanly reset:
   - Clear existing `.pdf`, `.docx`, `.xlsx`, `.md`, `.txt`, and `.json` artifacts from previous test runs so tests can never pass due to stale disk cache.
   - Re-create the empty directory structure before dispatching runners.
2. In `tools/penta-interface-e2e/src/cases/conversions_office_tools.rs`:
   - Verify that output existence checks assert the file was modified within the test execution window and has a file size > 0 bytes.

================================================================================
PART 2: TRUE IN-MEMORY ENGINE PARITY FOR WASM & EDGE
================================================================================
In `tools/penta-interface-e2e/src/cases/conversions_office_tools.rs`, `conversions_pdf_tools.rs`, and `analysis.rs`:
1. Replace simulated string assertions with genuine in-memory buffer execution:
   - For `office_to_markdown`:
     Load `test.xlsx` into memory as `&[u8]`, call `office_oxide` in-memory text/markdown conversion, and assert that the returned `String` contains valid Markdown table headers (`|` and `---`).
   - For `office_extract_text`:
     Pass raw file bytes in memory, invoke text extraction, and assert returned text contains non-empty text without XML tags.
   - For `office_modernize_legacy`:
     Read `test.xls` bytes in memory, execute legacy modernization, and assert the returned byte buffer starts with the ZIP magic header `PK\x03\x04`.
   - For `pdf_rag_chunks`:
     Load `single_page.pdf` bytes, run chunking in memory, and assert that chunks array has non-empty elements with page numbers and text.
2. Ensure both `InterfaceType::Wasm` and `InterfaceType::CloudflareEdge` test arms invoke memory-based byte processing and perform genuine semantic checks on the output buffer.
