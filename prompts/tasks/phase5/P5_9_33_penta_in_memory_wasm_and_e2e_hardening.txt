Task: Penta-Interface In-Memory WASM Parity & Sandboxed E2E Hardening [Spec 057]

Context:
The 5-Interface E2E suite (`tools/penta-interface-e2e`) has reached a 100% pass baseline across 1,041 tests. However, several WASM and Cloudflare Edge columns currently use simulated marker assertions (`[Simulated] WasmEngine call`). In addition, repeated test runs write to a shared output directory (`tests/e2e_fixtures/out/`), introducing the potential for stale-cache passes.

This task hardens the E2E suite by establishing true in-memory buffer execution for WASM/Edge, wiping test output sandboxes before runs, and expanding semantic validations in the Playwright suite.

CRITICAL CONSTRAINTS:
1. ZERO HARDCODED MOCKS: No dummy `passed: true` without asserting actual returned data/bytes.
2. WORKSPACE SAFETY: NEVER execute `git reset`, `git checkout -- .`, `git clean -fd`, or `git restore`.
3. CONCURRENCY: Maintain bounded concurrency (`-j 4`).

================================================================================
PART 1: SANDBOXED TEST RUN ISOLATION & DUAL-CHECK FILE VERIFICATION
================================================================================
In `tools/penta-interface-e2e/src/main.rs`:
1. Clean Run Guarantee:
   - Before running test suites, completely reset and wipe the temporary output directories (`tests/e2e_fixtures/out/penta_e2e*`):
   - Wipe all stale `.pdf`, `.docx`, `.xlsx`, `.md`, `.txt`, and `.json` artifacts from previous runs so tests can NEVER pass against old files.
   - Re-create a clean, empty output directory prior to running each suite.

2. Mandatory Dual-Check File Verification on Disk:
   Every test generating a file must perform a two-step validation:
   - Step 1 (Creation Check): Assert output file exists, is non-empty (> 0 bytes), and has a modification timestamp within the active test execution window.
   - Step 2 (Deep Semantic Inspection):
     - For PDFs (`merge`, `split`, `rotate`, `watermark`, `crop`): Use `PdfAssertions` to verify exact page counts, text strings on specific pages, rotation dictionary tags (`/Rotate 90`), and encryption locks.
     - For Office to Markdown (`office_to_markdown`): Verify file contains table syntax (`|` and `---`) and expected table headers.
     - For Office Text Extraction (`office_extract_text`): Verify plain text output contains expected text lines without XML tags.
     - For Office Modernization (`office_modernize_legacy`): Inspect the output file header and verify it opens as a valid OpenXML ZIP archive (`[Content_Types].xml`).
     - For Spreadsheets to JSON/CSV (`excel_to_json`, `excel_to_csv`): Parse JSON to verify expected column keys and array length; parse CSV to verify delimiter formatting.
