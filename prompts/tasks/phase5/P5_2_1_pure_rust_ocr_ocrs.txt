# Task: Phase 5.2.1 — Pure-Rust OCR Engine Migration (ocrs via rten)
# Base Branch: main
# Spec: specs/017-pure-rust-ocr-ocrs/spec.md

## Objective
Migrate `pdf_ocr` in `paperpilot-pdf/src/operations/ocr.rs` to use Robert Knight's **`ocrs`** (pure-Rust OCR engine powered by **`rten`**).
This completely eliminates external host C/C++ dependencies (`tesseract-ocr`, Leptonica) and makes OCR fully self-contained on CPU and portable to WebAssembly.

## 1. Dependency Configuration (`paperpilot-pdf/Cargo.toml`)

Add `ocrs` and `rten` to `paperpilot-pdf/Cargo.toml`:
```toml
ocrs = "0.10"
rten = "0.14"
rten-imageproc = "0.14"
```
*(Check and use latest compatible versions that compile cleanly with your Rust toolchain)*.

## 2. Implementation Details: `paperpilot-pdf/src/operations/ocr.rs`

### Architecture & Engine Wiring
1. Implement `OcrOperationImpl` adhering to `PdfOperation` trait:
   ```rust
   pub struct OcrOperationImpl {
       pub output_path: Option<PathBuf>,
       pub language: Option<String>,
   }
   ```
2. When executing on a document:
   - Extract embedded image streams or page graphics using `lopdf`.
   - Convert image bytes to dynamic images using the `image` crate (already in `paperpilot-pdf/Cargo.toml`).
   - Run `ocrs::OcrEngine` (text detection with DBNet, text recognition with CTC/Transformer decoder).
   - Collect recognized words, bounding boxes, and lines.
   - Inject text layer onto the PDF document and save to `output_path` if specified.
3. Fallback Mechanism:
   - If model weights are not loaded, gracefully fall back to extracting and preserving text content so that `OcrOperation` never panics.
