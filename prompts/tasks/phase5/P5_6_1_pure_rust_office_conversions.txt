## Objective
Eliminate slow `headless_chrome` execution (~2,500ms) across all 3 document conversion tools by migrating to pure-Rust engines:
1. **Excel to PDF (`pdf_convert_excel`)**: Replace Chromium browser launch with **`genpdf`** reading cell tabular matrices via **`calamine`** directly. Latency target: **< 25ms** (down from 2,500ms).

3. **HTML to PDF (`pdf_convert_html`)**: Replace Chromium browser launch with pure-Rust **`fulgur`** (pure-Rust HTML/CSS-to-PDF engine with CSS Paged Media `@page` support). Latency target: **< 50ms** (down from 2,750ms).

## 2. Implementation (`paperpilot-pdf/src/operations/conversion.rs`)

### A. Excel to PDF (`ExcelToPdfOperation`)
- Open the `.xlsx` / `.xls` workbook with `calamine`.
- Iterate through sheets and cells, extracting values and tabular grid layout.
- Build a structured vector PDF document using `genpdf` with clean borders, header formatting, and automatic column widths.
- Output directly to the specified destination PDF.
- **Latency Target**: Drop from ~2,500ms to < 25ms.

### B. Markdown to PDF (`MarkdownToPdfOperation`)
- Parse input markdown string or translate markdown elements into `typst` content/AST.
- Compile and export the document directly into vector PDF bytes using `typst::compile` / `typst_pdf`.
- Output crisp vector typography, headers, lists, code blocks, and blockquotes.
- **Latency Target**: Drop from ~2,400ms to < 35ms.

### C. HTML to PDF (`HtmlToPdfOperation`)
- Ingest input HTML string with resolved CSS styling (presets or custom CSS).
- Render directly to vector PDF bytes using `fulgur`.
- Eliminate all `headless_chrome::Browser` cold-start and tempfile browser spawning.
- **Latency Target**: Drop from ~2,750ms to < 50ms.

### D. Error Handling & Stability
- Graceful fallbacks: If an exotic font or unsupported layout element is encountered, fall back cleanly without panicking.
- Always generate a non-empty, valid PDF file conforming to `%PDF-` binary magic bytes.
