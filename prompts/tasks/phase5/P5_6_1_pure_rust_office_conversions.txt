## Technical Context & How Existing Code is Structured
In `paperpilot-pdf/src/operations/conversion.rs`:
1. `HtmlToPdfOperation`:
   - Takes `pub input_html: String`, `pub output_path: PathBuf`, `pub options: HtmlToPdfOptions`.
   - Has `pub fn render(&self) -> OperationResult<()>`.
2. `MarkdownToPdfOperation`:
   - Takes `pub input_md: String`, `pub output_path: PathBuf`, `pub options: HtmlToPdfOptions`.
   - Has `pub fn render(&self) -> OperationResult<()>`.
   - Already uses `pulldown_cmark::Parser` and `pulldown_cmark::html::push_html` to generate HTML, then calls `HtmlToPdfOperation::render()`.
3. `ExcelToStyledHtmlOperation`:
   - Takes `pub input_path: PathBuf`, `pub output_path: PathBuf`, `pub options: HtmlToPdfOptions`.
   - Parses sheets with `calamine::open_workbook_auto` (or CSV with `csv::Reader`), generates an HTML table with CSS, and delegates to `HtmlToPdfOperation::render()`.

Because `MarkdownToPdfOperation` and `ExcelToStyledHtmlOperation` already convert their documents to HTML, **upgrading `HtmlToPdfOperation` to pure-Rust automatically upgrades Markdown and Excel as well!**

## Concrete Requirements

### 1. Pure-Rust HTML to PDF (`HtmlToPdfOperation`)
- Add `fulgur = "0.40"` to `paperpilot-pdf/Cargo.toml`.
- In `HtmlToPdfOperation::render(&self)`:
  - Resolve and inject CSS as usual (`resolve_css`, `inject_css_into_html`).
  - Render directly to vector PDF bytes using `fulgur`.
  - Write bytes to `self.output_path`.
  - Remove all Chromium browser spawning, `headless_chrome::Browser::new`, `tab.navigate_to`, and `tempfile` browser scripts.
  - Latency target: `< 50ms`.

### 2. Markdown & Excel Latency Targets
- With `fulgur` replacing Chromium:
  - `MarkdownToPdfOperation`: `pulldown-cmark` parses in < 1ms, `fulgur` renders in ~15ms. Total latency: `< 25ms`.
  - `ExcelToStyledHtmlOperation`: `calamine` extracts rows in ~3ms, `fulgur` renders in ~15ms. Total latency: `< 25ms`.
- Ensure output PDFs start with valid `%PDF-` header bytes and are not empty.
