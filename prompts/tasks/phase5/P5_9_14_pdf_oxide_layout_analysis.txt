Task: Advanced Multi-Column & Table Document Layout Analysis via Spatial XY-Cut & docx-rs [Spec 039]

Objective:
Enhance PaperPilot's PDF-to-Word (`pdf_to_docx`) conversion engine by implementing spatial layout analysis
(recursive XY-Cut column de-weaving and table boundary recognition) in `paperpilot-pdf` and `paperpilot-wasm`,
so that multi-column PDFs retain proper reading order and tabular data emits native OpenXML tables (`docx_rs::Table`).

Context & Requirements:
- Read `specs/039-pdf-oxide-layout-analysis/spec.md`.
- Baseline: Spec 038 (`paperpilot-pdf/src/operations/conversion.rs` and `paperpilot-wasm/src/operations.rs`).
- Concurrency limit: Maximum 6 cores (-j 6).
- 100% pure Rust, zero native C dependencies, fully compatible with wasm32-unknown-unknown (<35MB RSS).

Implementation Steps:
1. TextSpan Extraction:
   - Extract `TextSpan` with `(x, y, font_size, is_bold, is_italic, color_hex)` during stream decoding in `paperpilot-pdf`.
2. XY-Cut Column De-Weaving:
   - Detect vertical column gutters (gutter width >= 15.0 pt).
   - Partition text spans into distinct vertical columns. Sort spans in Column 1 top-to-bottom before Column 2.
3. Table Recognition & docx-rs Table:
   - Detect clusters sharing consistent row Y values and column X alignments (>= 2 rows, >= 2 columns).
   - Map into `docx_rs::Table` with `TableRow` and `TableCell`.
4. WASM Parity:
   - Update `paperpilot-wasm/src/operations.rs` `pdf_to_docx` with identical pure-Rust XY-Cut sorting and table conversion.
5. Graceful Fallback:
   - Fall back to standard sequential paragraph extraction on single-column or ambiguous pages. Never panic.
