# Task: Phase 5.9.1 — Desktop Release Binary Size Optimization & Pure-Rust Inference Migration
# Base Branch: main
# Target Branch: feat-desktop-binary-optimization
# Priority: HIGH (Desktop Release Bloat Reduction)
# Spec: specs/028-desktop-binary-optimization/spec.md

## Objective
Reduce the standalone Desktop release executable size (`target/release/desktop`) from **107 MB down to < 75 MB** (~35-40% reduction) and eliminate C++ ONNX Runtime dependencies by:
1. Configuring the canonical workspace-level `[profile.release]` in the root `Cargo.toml` (`strip = true`, `lto = "fat"`, `opt-level = 3`, `codegen-units = 1`, `panic = "abort"`).
2. Removing the redundant/ignored `[profile.release]` in `apps/desktop/src-tauri/Cargo.toml` to eliminate Cargo workspace warnings.
3. Migrating `paperpilot-nlp` Layer 2 from Microsoft C++ `ort` to pure-Rust `rten` SIMD tensor engine (already used for OCR in `paperpilot-pdf`), eliminating `onnxruntime` C++ symbols.
4. Measuring, documenting, and validating Before & After binary sizes, symbol distributions, and latency benchmarks.

## 1. Requirements & Acceptance Criteria

### A. Root Workspace Release Profile
Update the root `Cargo.toml`:
```toml
[profile.release]
opt-level = 3
lto = "fat"
codegen-units = 1
panic = "abort"
strip = true
```
Remove `[profile.release]` from `apps/desktop/src-tauri/Cargo.toml`.

### B. Pure-Rust Inference Engine (`rten`) Migration
1. In `paperpilot-nlp/Cargo.toml`, replace `ort` with `rten` (version matching `Cargo.lock` ~0.21.0) and `rten-tensor`.
2. Convert or load the TinyBERT classification model into `.rten` format.
3. Update `paperpilot-nlp/src/layer2.rs` so `predict(&self, query: &str) -> Option<Intent>` executes in memory using `rten::Model` with sub-2ms latency.
4. Ensure all NLP unit and integration tests pass:
   ```bash
   cargo test -p paperpilot-nlp -j 2
   ```

### C. Build & Verification
1. Run `make build-release`.
2. Verify:
   - Output binary `target/release/desktop` is **< 75 MB**.
   - Binary is stripped (`file target/release/desktop` shows `stripped`).
   - Zero compilation warnings regarding ignored non-root profiles.
3. Document the Before vs. After results in:
   - `reports/DESKTOP_BINARY_OPTIMIZATION_REPORT.md`
   - `wiki/22-Desktop-Binary-Optimization.md`

Include the exact commands used to measure and analyze the binary:
- `ls -lh target/release/desktop`
- `file target/release/desktop`
- `nm -S -C target/release/desktop` (symbol breakdown)
- `python3 -c ...` breakdown script comparing ONNX vs. RTEN machine code.
