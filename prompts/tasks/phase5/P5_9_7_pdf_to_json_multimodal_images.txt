# Task: Phase 5.9.7 — Multimodal PDF-to-JSON with Image Extraction & Base64 Inlining
# Base Branch: main
# Target Branch: feat-pdf-to-json-multimodal-images
# Priority: MEDIUM (Multimodal AI & Document Vision Ingestion)
# Spec: specs/032-pdf-to-json-multimodal-images/spec.md

## Objective
Enhance `pdf_to_json` in `paperpilot-pdf` and all front-facing interfaces (CLI, MCP, REST Gateway) to support multimodal image extraction and optional Base64 inline embedding per [Spec 032](specs/032-pdf-to-json-multimodal-images/spec.md):

### Requirements:
1. **Schema Expansion**:
   - Add `JsonImage` struct with fields: `id`, `page_number`, `format`, `width`, `height`, `bbox`, `file_path`, and `base64_data`.
   - Update `JsonPage` in `paperpilot-pdf/src/operations/conversion.rs` to include `images: Vec<JsonImage>`.
2. **Image Mode Support (`--image-mode`)**:
   - `none`: Text-only extraction (default).
   - `files`: Extracts embedded images to disk and records relative `file_path`.
   - `base64`: Inlines images as standard data URIs (`data:image/png;base64,...`) via the pure-Rust `base64` and `image` crates.
3. **Interface Parity**:
   - **CLI**: Add `--image-mode <none|files|base64>` to `paperpilot convert`.
   - **MCP**: Add `image_mode` property to `pdf_to_json` schema in `paperpilot-mcp/src/server.rs`.
   - **REST API**: Expose `image_mode` in `/api/v1/pdf/convert` payload.
4. **Verification**:
   - Write tests in `paperpilot-pdf` verifying a PDF with embedded images produces valid Base64 data that decodes back to the original image dimensions.
   - Assert zero memory leaks on large multi-image PDFs.

## Deliverable
Run:
```bash
cargo test -p paperpilot-pdf -- conversion::test_pdf_to_json
```
Verify tests pass and document in `reports/PDF_TO_JSON_MULTIMODAL_REPORT.md`.
