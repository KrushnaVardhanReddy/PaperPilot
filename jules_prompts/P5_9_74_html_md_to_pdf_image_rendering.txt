Task: Implement Task 5.9.74 / Spec 088 — Full-Fidelity Image & Asset Rendering in HTML & Markdown to PDF Synthesis (`html_to_pdf`, `md_to_pdf`).

### Context & Problem Statement
In PaperPilot's Wave 3 Web & AI Synthesis Suite (`v0.7.0`):
- `pdf_to_html` / `pdf_to_markdown`: Extracts text and visual assets (raster photos and vector illustrations as base64 data URIs or image files).
- `html_to_pdf` / `md_to_pdf`: Synthesizes styled PDFs using pure-Rust `fulgur`.

Currently, `HtmlToPdfOperation::render()` in `paperpilot-pdf/src/operations/conversion.rs` initializes `fulgur::Engine::builder().build()` without an `AssetBundle`.
When an HTML document or Markdown text includes `<img src="...">` (data URIs or local file paths), `fulgur` skips the images or leaves an empty blank box, so synthesized PDFs only show text and CSS formatting.

### Architectural Solution & Implementation Details
In `paperpilot-pdf/src/operations/conversion.rs`:

1. **Asset Extraction & Registration**:
   In `HtmlToPdfOperation::render()`:
   - Use `scraper` (already in `paperpilot-pdf/Cargo.toml`) or `regex::Regex` to parse all `<img ... src="..." ...>` tags in `self.input_html`.
   - Instantiate `mut bundle = fulgur::asset::AssetBundle::new()`.
   - For each found `src` attribute:
     a) **Base64 Data URIs (`data:image/...;base64,<payload>`)**:
        - Strip the prefix (e.g. `data:image/png;base64,` or `data:image/jpeg;base64,`).
        - Decode the base64 payload into `Vec<u8>` using `base64::engine::general_purpose::STANDARD.decode()`.
        - Generate a unique asset name (e.g., `inline_img_0.png`, `inline_img_1.jpg`).
        - Call `bundle.add_image(asset_name.clone(), decoded_bytes)`.
        - Replace the original data URI `src` in the HTML string with `asset_name`.
     b) **Local File Paths (relative or absolute)**:
        - If the path is relative, resolve it relative to the parent directory of `self.output_path` or working directory.
        - If the file exists on disk, read its bytes: `std::fs::read(&resolved_path)`.
        - Generate an asset name (e.g. file name or sanitized key).
        - Call `bundle.add_image(asset_name.clone(), file_bytes)`.
        - Replace the file path in HTML `src` with `asset_name`.
     c) **Error Handling & Resilience**:
        - If any image fails to decode or read, log a warning via `eprintln!` or `log::warn!` and continue without panicking or aborting the document render.
   - Configure the engine with the asset bundle:
     ```rust
     let engine = fulgur::Engine::builder()
         .assets(bundle)
         .build();
     ```
   - Render the transformed HTML using `engine.render(&styled_html)`.

2. **Markdown to PDF Parity**:
   In `MarkdownToPdfOperation::render()`:
   - Markdown documents are converted to HTML via `pulldown_cmark::html::push_html`.
   - Ensure `HtmlToPdfOperation` receives the HTML so that both `![alt](data:image/png;base64,...)` and `![alt](path/to/img.png)` are automatically picked up and rendered into the PDF.

3. **Testing Requirements**:
   In `paperpilot-pdf/src/operations/conversion.rs` `tests` module:
   - `test_html_to_pdf_with_base64_image`:
     - Provide an HTML string containing `<img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk+M9QDwADhgGAWjR9awAAAABJRU5ErkJggg==" width="50" height="50">`.
     - Execute `HtmlToPdfOperation::render()`.
     - Verify the resulting PDF is non-empty, starts with `%PDF-`, and has valid length.
   - `test_md_to_pdf_with_base64_image`:
     - Provide a Markdown string with an embedded image `![Pixel](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk+M9QDwADhgGAWjR9awAAAABJRU5ErkJggg==)`.
     - Execute `MarkdownToPdfOperation::render()`.
     - Verify the generated PDF exists and starts with `%PDF-`.
   - `test_html_to_pdf_graceful_missing_image`:
     - Test that an invalid base64 or nonexistent image path does not panic and still renders the document text.
