## 3. Detailed Requirements

### A. Dynamic Arbitrary Tool Sequencing & Curated Recipes in `templates.py` & `generate_dataset.py`
The model must understand arbitrary multi-step combinations in ANY order requested by the user, not just hardcoded presets!
1. **Dynamic Arbitrary Tool Chaining Engine**:
   - Allow the generator to randomly sample **any 2 to 5 compatible tools** from `TOOLS_REGISTRY` (e.g. `[pdf_rotate, pdf_stamp, pdf_compress]`, `[pdf_extract_images, pdf_to_markdown]`, `[pdf_watermark, pdf_page_numbers, pdf_encrypt]`).
   - Dynamically chain inputs and outputs (`/tmp/inter_1.pdf` ➔ `/tmp/inter_2.pdf` ➔ final output file).
   - Generate varied conversational connector phrasing:
     - Sequential: *"First ..., then ..., and finally ... "*
     - Inverted intent: *"Before saving to {output} and compressing, please rotate it 90 degrees and add a watermark."*
     - Comma lists: *"Please watermark {input}, Bates stamp it, and scan for PII, outputting to {output}."*
     - Pipe syntax: *"input.pdf | rotate | compress | encrypt -> output.pdf"*
2. **Dedicated Curated Industry Recipes** (15 base presets):
   - Legal: `pdf_bates` ➔ `pdf_watermark` ➔ `document_pii_scan`
   - Clean Scan: `pdf_remove_blank` ➔ `pdf_auto_rotate` ➔ `pdf_ocr`
   - Sanitization: `pdf_redact` ➔ `pdf_sanitize` ➔ `pdf_linearize`
   - Secure Dist: `pdf_page_numbers` ➔ `pdf_encrypt`
   - Print Prep: `pdf_nup` ➔ `pdf_crop` ➔ `pdf_compress`
   - Collate: `pdf_merge` ➔ `pdf_compress`
   - Forensics: `pdf_validate_signatures` ➔ `pdf_extract_tables` ➔ `pdf_audit_log`
   - Booklet: `pdf_split_scanned_book` ➔ `pdf_auto_rotate` ➔ `pdf_booklet`
   - Archival: `office_modernize_legacy` ➔ `pdf_to_markdown` ➔ `pdf_compress`
   - Alternating: `pdf_merge_alternate` ➔ `pdf_page_numbers`
   - Forms: `pdf_flatten_annotations` ➔ `pdf_stamp` ➔ `pdf_encrypt`
   - Slides: `pdf_to_pptx` ➔ `office_extract_text`
   - Web Repair: `pdf_repair` ➔ `pdf_compress` ➔ `pdf_linearize`
   - Chapters: `pdf_split_by_outline` ➔ `pdf_extract_text`
   - Visual Diff: `pdf_compare_visual` ➔ `pdf_invert_colors`

### B. Parameter Chaining Engine in `generate_dataset.py`
In `generate_compound_workflow_record()`:
- Correctly wire intermediate files:
  - Tool 0 takes `main_input` (or `inputs` list for merge) and outputs to `/tmp/inter_1.pdf`.
  - Tool $i$ takes `/tmp/inter_{i}.pdf` as input and outputs to `/tmp/inter_{i+1}.pdf`.
  - Final Tool outputs to `main_output`.
- Extract and retain parameters mentioned in the prompt (passwords, watermark text, rotation angle, Bates prefix).
- Assistant output must be a strict JSON string representing a Python list: `json.dumps(steps)`.

### C. Distribution & Balancing in `generate_dataset.py`
- Ratios:
  - If random < `negative_ratio` (default `0.1`): generate negative refusal.
  - Elif random < `negative_ratio + compound_ratio` (default `0.1 + 0.4 = 0.5`): generate compound workflow record.
  - Else: generate single tool record.

### D. Unit Tests in `test_dataset_generator.py`
Add pytest test functions:
1. `test_compound_workflow_array_schema()`: Assert generated compound records parse as valid JSON arrays with $\ge 2$ tool dictionaries.
2. `test_intermediate_parameter_chaining()`: Assert the output of step $N$ matches the input of step $N+1$, and the last step writes to the target output.
3. `test_dataset_distribution_ratios()`: Generate 500 samples with `--compound-ratio 0.4` and verify compound records make up $40\% \pm 5\%$.
