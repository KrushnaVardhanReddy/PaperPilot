## 🏛️ ARCHITECTURAL GOALS & CONTEXT
In PaperPilot, adding any new tool requires wiring across 8 distinct directories across our 5-interface surface model (Core Rust, CLI, MCP Server, REST Gateway, WASM, Cloudflare Edge, Desktop UI, and Penta E2E Suite). Manually doing this for every tool introduces boilerplate fatigue and merge conflicts.

Build a standalone, pure-Rust CLI tool in `tools/penta-scaffold` that automatically generates 100% compiling boilerplate across all 5 surfaces from a single command.

---

## ⚠️ CRITICAL IMPLEMENTATION RULES & EXACT PATTERNS

### 1. Zero Python Mandate
The tool MUST be 100% pure Rust (using `clap`, `heck`, `anyhow`, standard library `fs` and string manipulation). Do NOT use Python scripts or python-based replacements!

### 2. MCP Server (`paperpilot-mcp/src/server.rs`) Exact Pattern
In `server.rs`, individual tool match arms inside `execute_call_tool` return `Ok(OperationResult { ... })`, NOT `CallToolResponse::Complete`!
`CallToolResponse::Complete` is handled once at the very bottom of `execute_call_tool`.

Your injected MCP match arm must look EXACTLY like this:
```rust
"{tool_name}" => {{
    let input = get_string("input")?;
    let output = get_string("output")?;
    ensure_parent_dir(&output)?;

    let input_bytes = std::fs::read(&input)
        .map_err(|e| rmcp::ErrorData::internal_error(e.to_string(), None))?;
    let options = paperpilot_pdf::operations::{snake_name}::{PascalCase}Options::default();
    let result = paperpilot_pdf::operations::{snake_name}::{snake_name}_bytes(&input_bytes, &options)
        .map_err(|e| rmcp::ErrorData::internal_error(e.to_string(), None))?;

    std::fs::write(&output, result)
        .map_err(|e| rmcp::ErrorData::internal_error(e.to_string(), None))?;

    Ok(OperationResult {{
        data: Some(serde_json::json!({{ "output_path": output }})),
        success: true,
        message: "{display_title} executed successfully".to_string(),
        output_path: Some(output),
        diff_detected: None,
    }})
}}
```

**CRITICAL RUST FORMAT RULE:** In Rust `format!` templates, literal JSON braces `{` and `}` MUST be escaped as `{{` and `}}`!

### 3. Core Operation Pattern (`paperpilot-pdf/src/operations/<name>.rs`)
Model directly after `paperpilot-pdf/src/operations/table.rs` and `sanitize.rs`:
- Provide `<PascalCase>Options` with `serde::{Serialize, Deserialize}` and `Default`.
- Provide `<snake_name>_bytes(input_bytes: &[u8], options: &<PascalCase>Options) -> Result<Vec<u8>, PdfError>` (or appropriate return type).
- Provide `<PascalCase>Operation` implementing `paperpilot_core::traits::PdfOperation`.
- Provide unit tests in `#[cfg(test)] mod tests` verifying empty document behavior.
- Add `pub mod <snake_name>;` into `paperpilot-pdf/src/operations/mod.rs`.

### 4. CLI Subcommand (`paperpilot-cli`)
- Add `<PascalCase> { input: PathBuf, output: PathBuf }` to `Commands` enum in `paperpilot-cli/src/cli.rs`.
- In `paperpilot-cli/src/commands/mod.rs`, add match arm routing to the command handler.

### 5. WASM & Desktop Catalog
- In `paperpilot-wasm/src/operations.rs`: Expose `pub fn {snake_name}(...)`.
- In `apps/desktop/src/lib/types/toolList.ts`: Append `ToolDefinition` item to `allTools` array with `inputFormat` and `outputFormat`.
