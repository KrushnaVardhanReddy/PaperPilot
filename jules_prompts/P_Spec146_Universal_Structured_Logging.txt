[Task / Spec 146: Universal Leveled & Structured Logging Engine]

Objective:
Implement Spec 146 (`specs/146-universal-structured-logging/spec.md`) to provide production-grade, leveled, and structured logging across `paperpilot-gateway`, `paperpilot-cli`, and `paperpilot-mcp`. Support `LOG_FORMAT=json|compact|pretty|text` and dynamic log levels via `RUST_LOG` / CLI flags.

---

### Critical Guardrails & Production Rules:

1. **System Resource Constraint**:
   ALWAYS run all cargo tests and builds with memory-safe `-j 4` (e.g. `cargo test -p paperpilot-gateway -j 4`).

2. **MCP Stdio Isolation (Zero Tolerance)**:
   In `paperpilot-mcp`, the MCP server uses `stdout` strictly for JSON-RPC messages. Under NO circumstances should application logs be written to `stdout`. All `tracing_subscriber` writers in `paperpilot-mcp` MUST be directed explicitly to `std::io::stderr`.

3. **Zero PII & Secret Redaction**:
   Never log raw document contents, decrypted text, or user passwords in log statements or JSON attributes. If passwords are provided in tool inputs, redact to `password="[REDACTED]"`.

4. **Zero-Mock Policy on Tests**:
   Write real integration tests verifying that stdout/stderr outputs actually contain valid NDJSON when `LOG_FORMAT=json` is set, and parse them with `serde_json::Value`.

---

### Step-by-Step Implementation Details:

#### Step 1: Axum HTTP Tracing Middleware in `paperpilot-gateway`
1. In `paperpilot-gateway/Cargo.toml`, ensure `tracing-subscriber` has features `["env-filter", "json"]`.
2. In `paperpilot-gateway/src/main.rs`:
   - Inspect `LOG_FORMAT` environment variable (`json`, `compact`, `pretty`, `text`). Default to `text`.
   - Configure `tracing_subscriber::fmt()` with `.with_env_filter(...)` and appropriate formatter (`.json()`, `.compact()`, `.pretty()`, or standard).
3. In `paperpilot-gateway/src/server.rs`:
   - Add an Axum tracing middleware layer (`tower_http::trace::TraceLayer` or custom middleware) that emits an `INFO` span on every HTTP request completion:
     - `http.method`: request HTTP method (GET, POST, etc.)
     - `http.route`: request path (e.g. `/api/v1/tools/pdf_compress`)
     - `http.status_code`: response status code integer (200, 400, 500)
     - `duration_ms`: latency elapsed in floating-point milliseconds
     - `client.ip`: client IP address if available
   - Ensure errors (status >= 500) emit at `tracing::error!` level and client errors (400–499) emit at `tracing::warn!` level.

---

#### Step 2: Global Log Flags in `paperpilot-cli`
1. In `paperpilot-cli/src/cli.rs`:
   - Add optional global flags to the root `Cli` struct:
     - `--log-format <text|json|compact|pretty>` (default: `text` or read from `LOG_FORMAT`)
     - `--log-level <trace|debug|info|warn|error>` (default: `info` or read from `RUST_LOG`)
2. In `paperpilot-cli/src/main.rs`:
   - Initialize `tracing_subscriber` before executing any subcommand.
   - Configure writer explicitly to `std::io::stderr` using `.with_writer(std::io::stderr)`.
   - Ensure stdout remains 100% clean for raw binary streams (e.g. `paperpilot merge ... > out.pdf`) and structured `--json` command outputs.

---

#### Step 3: MCP Stdio Protection in `paperpilot-mcp`
1. In `paperpilot-mcp/src/main.rs`:
   - Ensure `tracing_subscriber` is initialized targeting `std::io::stderr`:
     ```rust
     tracing_subscriber::fmt()
         .with_writer(std::io::stderr)
         .with_env_filter(...)
         .init();
     ```
   - Verify that running `paperpilot-mcp` emits JSON-RPC envelopes strictly on `stdout`.

---

#### Step 4: Automated Verification & Test Suite
1. Create `paperpilot-gateway/tests/test_logging.rs`:
   - Test that starting the gateway or making a request with `LOG_FORMAT=json` emits valid JSON containing `http.method`, `http.route`, and `http.status_code`.
2. Create `paperpilot-cli/tests/test_logging.rs`:
   - Execute CLI with `--log-format json` and verify stderr contains valid parseable JSON while stdout receives the operation output.
3. Run verification suite:
   - `cargo test -p paperpilot-gateway -j 4`
   - `cargo test -p paperpilot-cli -j 4`
   - `cargo test -p paperpilot-mcp -j 4`
