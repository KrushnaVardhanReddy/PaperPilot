# Task P158: Comprehensive 89-Tool Benchmark Suite, Standalone Runner Script, and Live Report Sync

## Objective
Build a unified, executable benchmark runner script (`scripts/run_system_benchmark.py` and/or `bench-penta-e2e` integration) that benchmarks all **89 canonical tools** in PaperPilot across CLI, MCP, and REST API. 
The script must:
1. Be runnable anytime from anywhere via `make benchmark` or `make bench-system`.
2. Generate an empirical, updated [`SYSTEM_BENCHMARK_REPORT.md`](SYSTEM_BENCHMARK_REPORT.md) covering all 89 tools.
3. Automatically update the calculated average execution speed in [`apps/web/src/components/BenchmarkMatrix.svelte`](apps/web/src/components/BenchmarkMatrix.svelte) and `README.md`.

---

## Technical Specifications & Requirements

### 1. Unified Benchmark Runner Script (`scripts/run_system_benchmark.py`)
Create a robust, self-contained Python script `scripts/run_system_benchmark.py` that can run headless in any environment:
- **Corpus & Fixtures**:
  - Uses existing real fixtures in `tests/e2e_fixtures/real/` (e.g. `bates.pdf`, `compressed.pdf`, `test.docx`, `test.xlsx`, `multimodal.pdf`, etc.).
  - Fallback: Synthesizes temporary benchmark scaling fixtures if needed (1, 10, 50, 100 pages) in a clean temporary directory.
- **Coverage**:
  - Benchmarks all **89 canonical tools** (or groups them across the 5 categories: Document Manipulation, Optimization & Security, Analysis & Rendering, Forms & Data, Conversions & Pipelines).
  - Automatically launches the local gateway daemon (`paperpilot serve --port 7823`) for REST API timing and kills it cleanly on exit.
  - Tests CLI latency, MCP latency, and Gateway REST latency per tool.
- **Metrics Collected**:
  - P50, P95, and P99 latency (ms).
  - Overall average latency across all tools (`avg_ms`).
  - Throughput (pages/sec or operations/sec).
  - Memory consumption (RSS in MB) sampled before and after runs.
  - Cold start vs warm start delta.

### 2. Auto-Generation of `SYSTEM_BENCHMARK_REPORT.md`
The script must format and write the complete findings to `SYSTEM_BENCHMARK_REPORT.md` at repo root:
- **Header**: System specifications (Platform, CPU model, total RAM, kernel version, timestamp).
- **Executive Summary Table**: Total tools tested (89/89), total invocations, average latency, WASM latency, zero-leak confirmation.
- **Category Latency Matrix**: Table showing each category, tools included, P50, P95, and throughput.
- **Individual Tool Scorecard**: Detailed table with tool ID, CLI latency, MCP latency, REST latency, and pass status.
- **Cold vs Warm Delta Table**.
- **Memory Footprint & Concurrency Summary**.

### 3. Frontend & README Synchronization
Once the script computes the real empirical average speed (e.g., `~12–25ms`):
- Update `apps/web/src/components/BenchmarkMatrix.svelte`:
  ```svelte
  <tr>
    <td class="feature-name">Execution Speed (avg)</td>
    <td class="highlight-col text-success">~{calculated_avg}ms (Native Engine) / &lt;1.1s (Full UI &amp; IPC)</td>
    <td class="text-warning">Network/Queue Dependent (2–15s)</td>
  </tr>
  ```
- Update any matching latency badges or benchmark numbers in `README.md`.

### 4. Makefile Integration
Add and expose standard targets in root `Makefile`:
```makefile
# Run comprehensive 89-tool benchmark suite and update SYSTEM_BENCHMARK_REPORT.md
.PHONY: benchmark bench-system
benchmark bench-system:
	python3 scripts/run_system_benchmark.py

# Run Phase 5.9.6: High-Throughput & Concurrency Performance Benchmark
bench-penta-e2e:
	cargo run -p penta-interface-e2e -- --group bench
```

## Step-by-Step Implementation Instructions

1. **Inspect Existing Test Harnesses**:
   - Review `scripts/test_tri_interface_e2e.py` and `tools/penta-interface-e2e/src/cases/bench.rs` to reuse existing command structures, arguments, and endpoints for all 89 tools.
2. **Develop `scripts/run_system_benchmark.py`**:
   - Ensure it handles `--quick` mode (1 iteration per tool) and full mode (multiple iterations for P50/P95/P99).
   - Ensure proper cleanup of child processes (Gateway daemon) using `try ... finally`.
   - Ensure it bypasses local proxy issues by using `127.0.0.1` and `--noproxy '*'` or explicit headers.
3. **Run Benchmark & Verify Output**:
   - Run `python3 scripts/run_system_benchmark.py`.
   - Verify `SYSTEM_BENCHMARK_REPORT.md` is populated with real numbers for all 89 tools.
4. **Update Frontend & Readme**:
   - Update `apps/web/src/components/BenchmarkMatrix.svelte` with the empirical average.
5. **Pre-Submission Verification**:
   - Run `make benchmark` to verify clean end-to-end execution.
   - Run `git status` to ensure only intended benchmark files and reports are touched.
   - Open Pull Request with description detailing benchmark results and hardware specs.
